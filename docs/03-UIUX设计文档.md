## 2. 设计原则

| 原则 | 说明 |
|---|---|
| 配置即所见 | 卡片直接暴露关键状态（启用、健康、映射模型），无需进入详情即可判断可用性 |
| 危险操作显性化 | 删除、清空、局域网暴露等破坏性/风险操作二次确认并用警示色 |
| 状态可观测 | 代理运行状态、Key 健康、故障转移、聚合过程全程可见，不做"黑盒" |
| 少即是快 | 常用操作（启用/停用、快切、复制接入配置）一步可达；高级配置折叠收纳 |
| 对齐习惯 | 布局、控件、深浅主题对齐 cc-switch，降低迁移用户的学习成本 |
| 中文优先 | 所有文案、错误、引导默认中文，术语与需求文档一致 |

## 3. 设计系统

### 3.1 主题与色彩

支持三种主题模式：浅色 / 深色 / 跟随系统（FR-023）。色彩以 shadcn/ui 的 CSS 变量体系组织，便于主题切换。

**中性色（背景/边框/文字）**

| 语义 Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `background` | `#FAFAFA` | `#0E0E11` | 应用主背景 |
| `surface` | `#FFFFFF` | `#18181B` | 卡片/面板背景 |
| `surface-hover` | `#F4F4F5` | `#232329` | 卡片悬停 |
| `border` | `#E4E4E7` | `#27272A` | 分隔线/描边 |
| `text-primary` | `#18181B` | `#FAFAFA` | 主文字 |
| `text-secondary` | `#71717A` | `#A1A1AA` | 次要文字/说明 |
| `text-muted` | `#A1A1AA` | `#52525B` | 占位/禁用 |

**品牌与功能色**

| 语义 Token | 色值 | 用途 |
|---|---|---|
| `primary` | `#6D5EF7`（靛紫） | 主按钮、选中态、代理运行强调 |
| `primary-foreground` | `#FFFFFF` | 主按钮文字 |
| `success` | `#22C55E` | 健康可用、代理运行中 |
| `warning` | `#F59E0B` | 未知/待检查、限流、映射缺口提示 |
| `danger` | `#EF4444` | 不可用、熔断、错误、删除 |
| `info` | `#3B82F6` | 提示、进行中 |

> 品牌主色 `primary` 采用靛紫，区别于 cc-switch 的默认色，形成 SynaRoute 自身识别度；如需完全对齐 cc-switch 可切换为其品牌色（评审确认）。

### 3.2 字体与字号

| 用途 | 字体 | 字号/字重 |
|---|---|---|
| 界面正文 | 系统 UI 字体（Windows: Segoe UI / 中文回退 Microsoft YaHei） | 14px / 400 |
| 卡片标题 | 同上 | 15px / 600 |
| 分区标题 | 同上 | 13px / 600（字距+0.02em，大写或加粗） |
| 说明文字 | 同上 | 12px / 400 |
| 代码/端点/密钥 | 等宽（Cascadia Code / Consolas） | 13px / 400 |

### 3.3 间距、圆角、阴影

- 间距基准 4px 栅格：`4 / 8 / 12 / 16 / 24 / 32`。
- 圆角：卡片 `12px`，按钮/输入 `8px`，徽标 `9999px`（药丸）。
- 阴影：卡片默认极轻阴影（`0 1px 2px rgba(0,0,0,.04)`），悬停/激活加深；深色模式以边框替代阴影为主。
- 窗口内容留白：主内容区左右 padding `24px`。

### 3.4 状态徽标（贯穿全局的视觉语言）

| 徽标 | 图标/色 | 含义 |
|---|---|---|
| 🟢 可用 | success 圆点 | 健康检查通过 |
| 🔴 不可用 | danger 圆点 | 探测失败/鉴权失败 |
| 🟡 未知 | warning 圆点 | 尚未检查/正在检查 |
| ⏸ 已停用 | 灰色圆点 | Key 未启用 |
| ⚡ 熔断中 | danger 描边 + 倒计时 | 连续失败被熔断，显示剩余冷却 |
| ★ 主 Key | primary 星标 | 故障转移优先级最高 |
| 🧠 聚合成员 | primary 脑标 | 参与大脑聚合 |

## 4. 信息架构与导航

采用「左侧主导航 + 顶部分类切换 + 右侧主内容」的经典桌面布局（对齐 cc-switch）。

```
应用（主窗口）
├── 顶部栏（Titlebar）：Logo/名称 · 代理状态总览 · 主题切换 · 最小化到托盘
├── 左侧主导航（Sidebar）
│   ├── 供应商配置（Providers）        ← 核心页，含三分类
│   ├── 无感切换（Routing）            ← 路由代理配置与状态
│   ├── 大脑聚合（Brain）              ← 聚合成员与决策者配置
│   ├── 运行日志（Logs）              ← 请求/切换/聚合可观测性
│   └── 设置（Settings）              ← 主题/安全/开机自启/导入导出
└── 系统托盘（常驻）：快切 · 开关代理 · 显示主窗口 · 退出
```

分类切换（Claude CLI / Claude 桌面端 / Codex 桌面端）作为「供应商配置」「无感切换」「大脑聚合」三页共享的顶部 Tab，切换时三页内容同步作用于当前分类。

```
顶部分类 Tab（贯穿 Providers / Routing / Brain）
┌───────────────┬──────────────────┬──────────────────┐
│  Claude CLI   │  Claude 桌面端   │  Codex 桌面端    │
└───────────────┴──────────────────┴──────────────────┘
        ▲ 当前选中分类以 primary 下划线 + 加粗标识
```

## 6. 关键界面设计

### 6.1 新增 / 编辑供应商 Key（抽屉面板）

从右侧滑出的抽屉（Sheet），不打断列表上下文。分「基础 / 模型 / 参数 / 映射」四段，长表单折叠收纳。

```
┌──────────────────────────── 新增供应商 Key ─────────────────────────┐
│                                                                     │
│  ① 基础信息                                                          │
│  名称（备注）   [ 厂商1 · Anthropic官方                       ]      │
│  厂商类型       [ Anthropic 兼容        ▾ ]  （预设 50+ / 自定义）   │
│  Base URL       [ https://api.anthropic.com                   ]      │
│  API Key        [ ••••••••••••••••••••••••••  ] [👁 显示]           │
│  自定义 Header   [ + 添加 ]                                          │
│                                                                     │
│  ② 模型                                              [⟳ 拉取模型]    │
│  上次拉取：2026-07-15 10:22                                          │
│  ☑ opus-4-6   ☑ opus-4-7   ☑ opus-4-8    [ + 手动添加模型 ]        │
│                                                                     │
│  ③ 参数                                                             │
│  temperature [0.7]  max_tokens [8192]  top_p [1.0]  超时(s) [60]    │
│                                                                     │
│  ④ 模型映射（可选）                                                  │
│  真实模型            期望模型名（工具请求名）                        │
│  [ GLM5.1     ▾ ] → [ opus-4-7                    ]   ✕            │
│  [ GLM5.2     ▾ ] → [ opus-4-8                    ]   ✕            │
│  [ + 添加映射 ]                                                     │
│                                                                     │
│                                   [ 测试连接 ]  [ 取消 ]  [ 保存 ]  │
└─────────────────────────────────────────────────────────────────────┘
```

要点：
- 「拉取模型」失败时（FR-004）表单不阻塞，就地降级为「手动添加模型」并显示错误原因（鉴权/网络/接口不存在）。
- API Key 默认掩码（FR-018/NFR-006），「显示」为临时查看。
- 「测试连接」触发一次健康检查，即时返回可用性，减少保存后才发现不可用。
- 参数非法值即时红框校验（FR-005）。

### 6.2 模型映射兜底提示（FR-006a 核心交互）

当用户在「无感切换」页选定目标期望模型集合后，系统计算各启用 Key 的覆盖情况，缺口以醒目卡片呈现，并提供一键补映射入口。

```
┌──────────────────────── ⚠ 模型映射缺口 ────────────────────────┐
│  你选定的目标模型：opus-4-7、opus-4-8                            │
│  以下 Key 缺少对应模型，故障转移切到它们时会失败：              │
│                                                                 │
│   厂商3 · GLM                                                   │
│     opus-4-7   ✅ 已映射 GLM5.1                                  │
│     opus-4-8   ❌ 缺失          [ 补充映射 → ]                   │
│                                                                 │
│  修复前无法保存/启用无感切换。                                   │
│                                        [ 稍后 ]  [ 逐项修复 ]   │
└─────────────────────────────────────────────────────────────────┘
```

- 端口冲突时自动改端口并同步更新接入配置文本（FR-008 验收）。

### 6.4 大脑聚合（功能2）

```
┌─────────────────────── 大脑聚合 · Claude CLI ─────────────────────┐
│  启用大脑聚合  [ ● 开启 ]        触发范围： 分类级全局 ▾           │
│  ──────────────────────────────────────────────────────────────   │
│                                                                    │
│  参与成员（并行解答）                              [ + 添加成员 ]  │
│   ┌────────────────────────────────────────────────────────────┐ │
│   │ 🧠 厂商1 · opus-4-8      🟢    ★ 主 Key            [移除]    │ │
│   │ 🧠 厂商2 · opus-4-7      🟢                        [移除]    │ │
│   │ 🧠 厂商3 · GLM5.2        🔴 不可用（本次将跳过）    [移除]    │ │
│   └────────────────────────────────────────────────────────────┘ │
│                                                                    │
│  聚合方式                                                          │
│   ● A 压缩汇总（省 token，先由汇总模型精炼再交决策者）             │
│   ○ B 全量上下文（把各成员完整答案交决策者）                       │
│                                                                    │
│  汇总模型（方式 A 专用）  [ 厂商2 · opus-4-7        ▾ ]           │
│  最终决策者              [ 厂商1 · opus-4-8         ▾ ]  ← 必填    │
│                                                                    │
│  总超时      [ 60 ] s      并行上限  [ 3 ]                         │
│  兜底策略    全部成员不可用时  ● 回退普通路由  ○ 报错             │
│                                                                    │
│                                              [ 恢复默认 ] [ 保存 ] │
└────────────────────────────────────────────────────────────────────┘
```

要点：
- 「汇总模型」是本项目确认的方式 A 实现（专门调一个模型做压缩汇总），因此在方式 A 下必须可配一个汇总模型（可复用某成员/决策者，也可独立指定）。
- 未配置「最终决策者」时开启开关被禁用并提示（FR-014 验收）。
- 不可用成员实时标红并注明「本次将跳过」（FR-015），不阻塞开启。

## 7. 关键交互流程（用户旅程）

### 7.1 首次配置到工具连通（对应 UC-006，目标 5 分钟内）

```
启动 App
  → 供应商页「＋ 新增供应商 Key」
  → 填基础信息 → 拉取模型（失败可手动录入）
  → 保存并「测试连接」🟢
  → 启用开关打开
  → （仅 1 个）系统提示「单 Key 直连，接入配置已就绪」
     或（≥2 个）横幅提示「无感切换已开启」→ 进无感切换页
  → 「一键写入 Claude CLI 配置」（二次确认 + 备份）
  → 目标工具发起请求 → 日志页看到 ✔ 转发
  → ✅ 连通
```

### 7.2 多 Key 无感切换配置（对应 UC-002）

```
配置厂商1/2/3 三个 Key（厂商3 配 GLM 映射）
  → 无感切换页选定目标模型 opus-4-7、opus-4-8
  → 系统兜底检查 → 若厂商3 缺 opus-4-8 映射 → 缺口卡片「补充映射」
  → 补齐 → 缺口清空
  → 拖拽设厂商1 为主 ★
  → 「一键写入」→ 完成
```

### 7.3 破坏性操作确认（贯穿）

删除 Key / 清空日志 / 开启局域网监听 / 覆盖写入工具配置 —— 均弹出确认对话框，说明影响与是否可逆，破坏性按钮用 danger 色，默认焦点在「取消」。

```
┌──────────── 确认删除 ────────────┐
│ 删除「厂商1 · Anthropic官方」？   │
│ 该 Key 的密钥与映射将被移除，     │
│ 无法恢复。若正被用作主 Key，       │
│ 故障转移顺序会自动调整。          │
│                                   │
│            [ 取消 ]  [ 删除 ]     │  ← 删除为 danger 色
└───────────────────────────────────┘
```

## 9. 状态、空态与错误

| 场景 | 呈现 |
|---|---|
| 分类下无 Key | 空态插画 + 「＋ 新增第一个供应商 Key」引导按钮 |
| 拉取模型失败 | 抽屉内就地红条 + 原因 + 「手动添加模型」降级 |
| 全部 Key 不可用 | 顶部栏红色告警 + 日志明确错误（NFR-009/NFR-013） |
| 端口冲突 | 自动换端口 Toast 提示，并更新接入配置 |
| 映射缺口 | 缺口卡片拦截保存（6.2） |
| 聚合超时收敛 | 过程视图标记超时成员为「已跳过」，用已到结果继续 |
| 加密未解锁（主口令模式） | 启动时锁屏输入口令，解锁后进入 |

所有错误文案遵循「发生了什么 + 建议动作」的中文两段式，例如：
> 「厂商1 鉴权失败（401）。请检查 API Key 是否有效，或前往编辑重新填写。」

## 10. 可访问性与细节

- 键盘可达：Tab 顺序合理，主要操作有快捷键（新增 `Ctrl+N`、搜索 `Ctrl+F`）。
- 颜色不作唯一信号：健康状态除颜色外附图标/文字（🟢可用 / 🔴不可用），满足色盲可辨。
- 对比度：正文与背景对比度满足 WCAG AA（≥4.5:1）为设计目标；最终需实测验证。
- 焦点可见：所有可交互元素有清晰 focus ring（primary 色）。
- 文案国际化预留：文案集中管理，便于后续多语言（当前中文优先）。

> 说明：完整无障碍达标需后续用辅助技术实测与专家评审，本节为设计目标而非合规结论。
