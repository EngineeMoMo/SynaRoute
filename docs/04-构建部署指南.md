## 2. ⚠️ 头号坑点：生产 exe 必须用 `tauri build`，禁止裸 `cargo build`

### 2.1 现象

部署后启动 `synaroute.exe`，界面打不开，WebView2 报：

```
嗯… 无法访问此页面
localhost 拒绝连接。
ERR_CONNECTION_REFUSED
```

### 2.2 根因

Tauri 应用的前端有两种加载方式，由构建方式决定：

| 构建命令 | 前端来源 | 结果 |
|---|---|---|
| `cargo build --release`（❌ 错误） | 运行时连 `devUrl`（`http://localhost:1420`） | 前端**没有嵌入**二进制；生产环境没有 dev server，连接被拒 → `ERR_CONNECTION_REFUSED` |
| `tauri build`（✅ 正确） | 编译期把 `frontendDist`（`../dist`）**嵌入**二进制 | 前端随 exe 分发，离线可用 |

关键：**裸 `cargo build` 不会执行前端构建、不会嵌入 `dist`、不会关闭 devUrl 回退**。它只编 Rust 部分，产出的 exe 是"半成品"，只能在 `npm run dev` 已启动的开发机上跑。

配置见 [`src-tauri/tauri.conf.json`](../src-tauri/tauri.conf.json)：

```jsonc
"build": {
  "frontendDist": "../dist",              // tauri build 时嵌入这里
  "devUrl": "http://localhost:1420",      // 仅 dev 用；裸 cargo build 会错误地回退到这里
  "beforeBuildCommand": "npm run build"   // tauri build 会先跑它重建前端；cargo build 不会
}
```

### 2.3 正确构建命令

```bash
# 在项目根目录（E:\workCode\ccCode\SynaRoute）执行

# 出正式安装包（NSIS）——交付用
npm run tauri build

# 只出 exe、不打安装包（日常快速验证用，更快）
npm run tauri build -- --no-bundle
```

产物路径：`src-tauri/target/release/synaroute.exe`

> 注意：`beforeBuildCommand` 已配为 `npm run build`，所以 `tauri build` 会**自动重建前端**。
> 不需要（也不应该）先手动 `npm run build` 再单独 `cargo build`——那正是踩坑的路径。

### 2.4 部署前必做的可证伪验证

**编完不要直接推。** 用以下命令确认前端确实嵌入了二进制，再部署：

```bash
# 1. 取当前前端 chunk 名
ls dist/assets/

# 2. 验证 exe 里含该 chunk 名（嵌入成功应 > 0；裸 cargo build 产物为 0）
grep -c "index-XXXXXXXX.js" src-tauri/target/release/synaroute.exe   # 用上一步实际文件名

# 3. 体积旁证：tauri build 产物比裸 cargo build 产物大约 10 万字节（前端资源的重量）
```

判据：**exe 内含前端 chunk 名 = 嵌入成功**。这是决定性证据。
（不要用 "exe 里是否含 `localhost:1420`" 判断——该串在正常 build 的配置数据段里也存在，无鉴别力。）

## 3. 部署流程（改配置/二进制前必备份，见 dev 硬规则）

```bash
# 1. 备份当前线上 exe（带日期与用途后缀，可回滚）
cp -f "F:/SynaRoute/synaroute.exe" "F:/SynaRoute/synaroute.exe.bak-<用途>-$(date +%Y%m%d-%H%M)"

# 2. 部署新 exe
cp -f "src-tauri/target/release/synaroute.exe" "F:/SynaRoute/synaroute.exe"

# 3. 部署后再校验一次前端 chunk 命中
grep -c "index-XXXXXXXX.js" "F:/SynaRoute/synaroute.exe"   # 应 = 1
```

> 部署目标 `F:\SynaRoute\synaroute.exe` 是本机当前运行位置，属环境相关信息，非硬编码进代码——代码内路径一律动态解析（dev 硬规则 2）。

## 4. 运行数据位置（排障参考）

| 文件 | 路径 | 说明 |
|---|---|---|
| 配置（不含密钥） | `%APPDATA%\SynaRoute\config.json` | key 列表、启用状态、优先级、映射等 |
| 加密密钥库 | `%APPDATA%\SynaRoute\secrets.enc` | DPAPI/AES 加密，绝不经 IPC 明文下发前端 |

落盘相关的并发竞态与静默吞错问题，见架构文档 NFR-011 及 `src-tauri/src/secret.rs` 的 `atomic_write`。

## 5. 快速自查清单

- [ ] 用的是 `npm run tauri build`（不是 `cargo build`）
- [ ] `dist/assets/` 里的 chunk 名能在产物 exe 里 grep 到（> 0）
- [ ] 产物体积正常（约 1.9 MB 量级，明显大于裸 cargo build 产物）
- [ ] 部署前已备份线上 exe
- [ ] 部署后再次 grep 校验前端 chunk 命中
