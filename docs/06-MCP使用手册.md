# SynaRoute MCP 使用手册

> 面向最终用户：如何在 Codex CLI / Claude Code 中接入 SynaRoute 的多模型大脑聚合能力。
> 配套设计文档见 [05-MCP集成设计.md](05-MCP集成设计.md)。

## 1. 这是什么

SynaRoute 内置一个 MCP（Model Context Protocol）服务器。开启后，你可以在 **Codex CLI**、**Claude Code** 等支持 MCP 的 AI 编程客户端里，直接调用 SynaRoute 的**多模型大脑聚合**：

- 多个模型**并行**分析你当前项目的代码
- 由**决策者**综合所有意见，输出一份清晰的建议 / 修改计划
- 建议返回给你的客户端，**由客户端自己执行文件修改**（用它原生的编辑工具 + 审批 UI）

**SynaRoute 只出主意，不碰你的文件。** 所有实际改动都经过你在客户端里的确认。

## 2. 前置条件

1. SynaRoute 桌面端已安装并运行
2. 至少在一个分类（Claude CLI / Claude 桌面端 / Codex）下：
   - 配好可用的 Key（有密钥、健康检查通过）
   - 在「大脑聚合」页启用聚合，并配好**参与者**和**决策者**
3. 客户端（Codex CLI ≥ 支持 HTTP MCP 的版本 / Claude Code）已安装

## 3. 开启 MCP 服务器

1. 打开 SynaRoute → **设置** → **MCP 服务器**
2. 打开「启用 MCP 服务器」开关
3. 端口默认 **9527**。**注意：如果 9527 被系统进程占用（部分 Windows 机器上 9527/9528 被 WUDFHost、指纹服务等占用），SynaRoute 会自动向上寻找空闲端口（9527~9547）。**
4. 卡片上的「接入地址（按分类）」列出三条地址、显示的是**实际绑定的端口**——请按你要接的客户端复制对应那一条。
   **地址末尾的分类段（`/claude-cli`、`/codex`、`/claude-desktop`）不能省**：SynaRoute 靠它判断这次调用属于哪个分类，进而用哪套 Key 池与聚合配置。省掉它会被当成「认不出的调用方」而退回默认分类
5. 状态指示灯变绿 = 服务正在运行；若变红，鼠标悬停查看失败原因

> ⚠️ 因为端口可能自动 fallback，**务必从设置页复制真实地址**，不要想当然写 9527。
>
> 更省事的做法：直接在「大脑聚合」页点该分类的「接入」按钮 —— 端口与分类段都由 SynaRoute 自己写，无需手工编辑任何文件。

## 4. 接入 Codex CLI

### 4.1 配置 MCP 连接

编辑 `~/.codex/config.toml`（Windows：`C:\Users\<你>\.codex\config.toml`），加入：

```toml
[mcp_servers.synaroute]
url = "http://127.0.0.1:9529/mcp/codex"   # ← 用设置页显示的真实地址（末尾分类段不能省）
```

> 端口以 SynaRoute 设置页「接入地址」为准。示例里是 9529（9527/9528 被占时的 fallback 结果）。

### 4.2 Hook（钩子）：让 Codex 主动调用

在项目根目录的 `AGENTS.md` 里加一段提示词，引导 Codex 在合适场景调用：

```markdown
## 多模型协作
遇到复杂的代码审查、架构设计、疑难排查任务时，优先调用 synaroute_ai 工具，
传入当前项目的绝对路径作为 cwd，获取多个模型的综合分析后再动手。
```

### 4.3 使用

在 Codex 里正常提问，例如：

```
用 synaroute 帮我审查一下 src/auth 模块的安全性
```

Codex 会调用 `synaroute_ai`，SynaRoute 聚合多个模型的意见后返回建议。你确认后，由 Codex 自己改文件。

## 5. 接入 Claude Code

### 5.1 配置 MCP 连接

在项目的 `.claude/settings.json`（或用户级 `~/.claude/settings.json`）里加：

```json
{
  "mcpServers": {
    "synaroute": {
      "url": "http://127.0.0.1:9529/mcp/claude-cli"
    }
  }
}
```

> 端口同样以设置页真实地址为准。

### 5.2 Hook（钩子）

Claude Code 支持在 `.claude/settings.json` 里配置 hooks。示例：当输入包含「审查 / review / 重构」等词时，提示优先走多模型分析：

```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "matcher": "review|审查|重构|refactor",
        "hooks": [
          { "type": "prompt", "prompt": "优先调用 synaroute_ai 做多模型分析，传入项目绝对路径作为 cwd" }
        ]
      }
    ]
  }
}
```

### 5.3 使用

正常对话，Claude Code 会在合适时调用 `synaroute_ai`。

## 6. 工具参数说明

`synaroute_ai` 接受以下参数：

| 参数 | 必填 | 说明 |
|------|------|------|
| `prompt` | 是 | 任务描述，如「审查鉴权模块的安全性」 |
| `cwd` | 否 | 当前项目根目录绝对路径。**强烈建议传入**，否则 SynaRoute 用自动跟随的最近活跃项目 |
| `languageHint` | 否 | 回答语言，如 `zh` / `en`，省略则跟随 prompt |
| `images` | 否 | 要一起看的图片，**相对 `cwd` 的路径**数组（如 `["docs/error.png"]`）。传了它必须同时传 `cwd` |

> **没有 `category` 参数** —— 用哪个分类的 Key 池与聚合配置，由「你从哪个客户端调进来的」自动决定，
> 不需要你或模型指定。判据写在接入信息里：Claude CLI 是接入地址末尾的分类段（`…/mcp/claude-cli`），
> Codex 与 Claude 桌面端是启动参数里的 `--mcp-category=…`（点「接入」按钮时自动写好）。
> 所以**一个客户端就对应一个分类**，想换分类就去那个分类页点「接入」。
>
> 早期版本有这个参数，问题是模型根本不知道自己活在哪个客户端里 —— 它只能反问你，
> 或者省略后被当成 `claude-cli`，于是用错 Key 池、额度记在别的分类头上、日志还落错页。

### 6.1 图片输入（`images`）

用于「这个报错截图是什么问题」这类需要看图的任务。限制与失败口径：

- 最多 **4 张**、单张 **≤ 5MB**，仅 `png` / `jpg` / `jpeg` / `gif` / `webp`
  （这四种是 Anthropic 与 OpenAI 协议**共同**支持的格式）。
- 路径必须在工作目录内：`..`、绝对路径、盘符/UNC，以及指向工作目录外的符号链接都会被拒。
- 凭据类文件名（`.env*`、密钥、证书）一律拒读——图片入口同样过这道防线。
- **任何一项不满足即整次调用报错并说明原因，不会静默丢掉某张图**。静默丢会让你拿到一个
  看起来正常、实则没看图的答案。
- 参与者模型必须支持图片输入。纯文本模型会被上游回 4xx，此时失败原因里会附
  「该模型可能不支持图片输入」的提示。

### 6.2 参与者按需检索（工具调用）

默认**关闭**，需在桌面端「大脑聚合 → 工具调用」里按分类开启。开启后参与者可用一组**只读**
工具自己决定看哪些文件：读文件（可指定行区间）、正则搜索、列目录、查符号索引（codegraph）。

- 需要工作目录：由本工具的 `cwd` 提供，或桌面端开了「自动跟随」/ 填了工作目录。三者都没有时
  该轮不提供工具（运行日志会写明原因）。
- 工具**只读**，永不写文件、不执行命令；限制在工作目录内，凭据类文件一律拒读。
- 有轮数上限（默认 6，可调 2~12）。到顶后会要求模型基于已获得的信息直接出结论。
- **会明显增加额度消耗**：每一轮工具调用都要把完整对话历史重发一次。

## 7. 返回内容

工具返回 Markdown 文本，包含：

- 🧠 综合分析 / 修改计划
- 参与模型列表
- 决策者、检索文件数、耗时
- 提示：请用你自己的编辑工具执行修改

## 8. 多项目隔离

每次工具调用带自己的 `cwd`，独立成一次聚合任务：

- 项目 A 和项目 B 的聚合**各自独立并发**，互不影响
- 你在 Codex 项目 A 里调用 → 分析项目 A 的代码
- 切到项目 B 调用 → 分析项目 B 的代码
- 参与者、决策者上下文完全隔离

## 9. 日志

MCP 调用会记录到：

- SynaRoute「运行日志」页（类型标 `mcp`）
- 软件安装目录下的 `logs/YYYY-MM-DD.jsonl`（或设置里自定义的日志目录）。
  单个文件写满 16MB 会滚出 `YYYY-MM-DD.1.jsonl`、`.2.jsonl`，同一天的内容按序号先后排列

每条记录含：时间、工作目录、参与者数、检索文件数、耗时、成功/失败。

## 10. 常见问题

**Q：状态灯是红的 / 客户端连不上？**
1. 确认设置里开关已打开、状态灯为绿
2. **用设置页显示的真实地址**（端口可能不是 9527）
3. 悬停红灯查看失败原因；若提示端口全被占用，在设置里手动换一个端口（如 18527）

**Q：工具调用返回「『某某』未启用大脑聚合」？**
报错里点出的就是这次调用被判定的分类（由接入地址 / 注册形态决定，见第 3 节）。去「大脑聚合」页切到**那个**分类，启用聚合并配好参与者 + 决策者。

**Q：返回「未配置最终决策者」？**
大脑聚合页必须选一个决策者才能工作。

**Q：SynaRoute 会自己改我的文件吗？**
不会。MCP 通道只返回建议，所有文件修改都由你的客户端执行并经你确认。

**Q：安全吗？**
MCP 服务器只监听 `127.0.0.1`（本机），不对外网开放，不需要鉴权。

## 11. 关闭

设置 → MCP 服务器 → 关闭开关。服务立即停止，下次启动不再自动运行。

## 12. 已知限制（当前版本）

以下是当前版本明确的能力边界，均为有意取舍，后续版本可能改进：

**文件检索**
- 检索优先用 `ripgrep`（若系统已安装，速度最快）；未安装时自动回退到内置的纯 Rust 目录遍历，功能不受影响，只是稍慢。
- 纯 Rust 兜底遍历有成本上界：最大深度 5 层、最多扫描 3000 个文件、只扫常见文本类扩展名（`.rs/.ts/.py/.md` 等），跳过 `node_modules/target/dist/.git` 等目录。超大仓库可能漏检深层文件。
- CodeGraph 索引检索仅在目标项目已有 `.codegraph/` 目录且系统装了 `codegraph` CLI 时生效，否则自动跳过（不影响 grep / 遍历检索）。

**协议 / 模型**
- 大脑聚合内部对参与者与决策者的调用是**非流式**的（等完整响应，不逐 token 推送）。这是有意取舍：
  必须等所有参与者的结论都齐了才能进决策环节，流式对最终耗时没有帮助。
- 参与者调用**已支持图片输入**（见 §6.1）与**按需检索的工具调用**（见 §6.2，默认关闭）。
- 代理转发（非 MCP 通道）的跨协议翻译以 Chat Completions 为中枢，Anthropic / OpenAI Chat /
  OpenAI Responses 三者**两两之间**的请求体、非流式响应体均可互转；**流式（SSE）也已补齐六个
  方向**（`upstream/sse.rs` 的 `SseDirection`）。**跨协议故障转移不再需要关闭流式。**
- 跨协议转换覆盖文本与**工具调用**（`tool_use` ↔ `tool_calls`、`tool_result` ↔ `role:"tool"`），
  但**不覆盖图片等多模态块**：`upstream/convert.rs` 只拆 `text` / `tool_use` / `tool_result`
  三类，其余块被丢弃。要在代理通道里发图，请让下游协议与该 Key 的上游协议一致走同协议透传；
  MCP 通道的 `images` 参数不受此限（那条路径按目标协议原生构造图片块）。

**工作目录自动跟随**
- 自动跟随支持 Claude CLI（`~/.claude/projects`）和 Codex（`~/.codex/sessions`）的会话历史。
- Claude 桌面端不落盘可解析的项目路径，仅在用户于桌面端建过 git worktree（`git-worktrees.json` 有记录）时能补充识别，否则无法自动跟随——请显式传 `cwd`。

**性能**
- 密钥解密（Windows DPAPI）为同步调用，在参与者并发聚合时会短暂占用异步线程。因单次解密在毫秒级、并发数受信号量限制（默认 3–5），实际影响可忽略。

**安全**
- MCP 服务器不鉴权，仅监听 `127.0.0.1`。同一台机器上的其他本地进程理论上也能调用它——单机个人使用场景下可接受。
- 启用主口令模式时，加密密钥用随机盐 + Argon2 派生，随密钥库落盘。
