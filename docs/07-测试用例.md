# SynaRoute 测试用例清单

本清单覆盖 SynaRoute 桌面端全部功能。按模块分组，每条用例可独立打勾。

**测试环境准备**
- Windows 11，已安装 SynaRoute（`F:\SynaRoute\synaroute.exe`）
- 至少准备 2 个可用的上游 Key：建议 1 个 Anthropic 协议、1 个 OpenAI 协议（用于跨协议测试）
- 已安装 Claude Code CLI 和/或 Codex（用于工具接入与自动跟随测试）
- 建议装 `ripgrep`（测检索主路径）；再单独找一台没装 rg 的场景测兜底（或临时改 PATH）

**结果记录说明**：每条用例末尾「实际」栏，测试时填 ✅通过 / ❌失败（附现象）/ ⚠️部分通过。

## 7. 流式透传（SSE，本轮新增）

> 前置：客户端发 `"stream": true`，且下游协议 == 该 Key 协议（同协议）。

| ID | 场景 | 步骤 | 预期结果 | 实际 |
|----|------|------|----------|------|
| 7.1 | 同协议流式基本 | Anthropic 客户端 → Anthropic Key，stream:true | 响应边生成边返回（增量可见），非等整段完成 | |
| 7.2 | content-type 正确 | 抓包/看响应头 | content-type 为 `text/event-stream`（上游真实值），不是 application/json | |
| 7.3 | 长回答不超时 | 请求一个长回答 | 流式不设 30s 总超时，长回答完整返回不被掐断 | |
| 7.4 | 流式前故障转移 | 首个 Key 返回非 2xx（首字节前） | 状态码探测阶段可安全切下一个 Key | |
| 7.5 | 流式中不切换 | 流已开始后上游断 | 不再切 Key（标准行为），错误如实反映 | |
| 7.6 | OpenAI 同协议流式 | OpenAI 客户端 → OpenAI Key，stream:true | 流式正常透传 | |
| 7.7 | Claude Code 真机流式 | Claude Code 指向代理，正常对话 | 打字机效果流畅，无卡顿到整段才出 | |

## 8. 跨协议转换（本轮新增响应翻译）

> 前置：下游协议 ≠ Key 协议。**注意：跨协议 + 流式暂不支持**，测试时对跨协议 Key 关闭流式。

| ID | 场景 | 步骤 | 预期结果 | 实际 |
|----|------|------|----------|------|
| 8.1 | Anthropic 客户端 → OpenAI Key（请求转换） | 下游 /messages，Key 是 OpenAI，非流式 | 请求体正确转为 OpenAI Chat Completions 格式 | |
| 8.2 | Anthropic 客户端 → OpenAI Key（响应翻译） | 同上，看客户端收到的响应 | 响应体翻译回 Anthropic Messages 格式（content[].text / stop_reason / usage.input_tokens），客户端能正常解析 | |
| 8.3 | OpenAI 客户端 → Anthropic Key（请求转换） | 下游 /chat/completions，Key 是 Anthropic | 请求体转为 Anthropic Messages 格式 | |
| 8.4 | OpenAI 客户端 → Anthropic Key（响应翻译） | 同上，看响应 | 响应翻译回 OpenAI 格式（choices[0].message.content / finish_reason / usage.prompt_tokens / object / total_tokens） | |
| 8.5 | stop_reason 映射 | 触发 max_tokens 截断 | Anthropic max_tokens ↔ OpenAI length 正确互转 | |
| 8.6 | system 消息处理 | 请求带 system | Anthropic system 字段 ↔ OpenAI system 消息正确转换 | |
| 8.7 | 非 2xx 不翻译 | 跨协议时上游报错 | 错误体原样透传（便于日志看上游真实错误），不做翻译 | |
| 8.8 | 跨协议流式的边界 | 跨协议 Key 开流式 | 已知限制：不支持 SSE 双向翻译（文档已注明），验证提示/降级行为符合文档 | |

- 跨协议转换仅覆盖纯文本消息
