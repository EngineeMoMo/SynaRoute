### 修复建议

- **A7-1**：`persist()` 开头（降级守卫之后）取一把进程级 `Mutex<()>`，把「序列化 + 落盘」整段纳入互斥。锁序 `persist_lock → config.read()` 与 `persist_lock → WRITE_LOCK` 均无环，且无调用方持 config 锁跨 `persist`。代价约 100 µs 串行化，而写本来已被 `WRITE_LOCK` 串行。⚠️ `store.rs` 生产段 2844，`ratchet.json` 冻结 2902 —— 有余量，但仍需为那把锁与理由注释腾 4 行左右。
- **A7-2**：`let pending = std::mem::take(&mut self.tool_calls);` 换掉 `.clone()`。语义逐字等价（`emit_anthropic_tool_block` 不碰 `self.tool_calls`，已核），且重复调用契约由「take 后为空 → 早退」保持。净 +0~1 行。<br>🔴 **不要改成游标版本**（只发新增的）：那会静默丢掉「name 在 `finish_reason` 之后才到」的工具调用，而该维度**零测试覆盖**，改坏了会全绿通过。
- **A7-3**：给累积总量加上限（同 `TAIL_WINDOW_BYTES` / `REQ_LOG_CAP` 的既有做法），越界**拒绝并只警告一次**（同 `tool_slot`）。⚠️ 不要钳制：把不同增量挤进同一个槽会拼出参数错乱的工具调用，比丢一条增量糟。
- **A7-4**：只改注释，从 `REQ_LOG_CAP` **派生**表述（「500 × 2 × REQ_LOG_CAP 字符」）而不是再抄一个数字，并写明 `cap_to` 数 char 不数 byte、折叠替换这个前提、以及「流式只有一个大 body」这一点。净零行数。<br>**共 6 处同源分叉**（已逐处自核）：`store.rs:874`「各上限 20000 字符 —— 500 条满载约 19 MB」、`store.rs:882`「≈2000 万字符（≈19 MB）」、`store.rs:164`「trace 正文可达 4 万字符」（= 2×20000）、`lib.rs:454`、`proxy.rs:702`「正文可达 2×20000 字符」。<br>🔴 **第 6 处是真漂移不只是过时**：`aggregate.rs:55` 的 `AGG_LOG_CAP = 20_000` 注释写「**与调用模型日志同量级**」—— 那个量级现在是 65536，**差 3.3 倍，这句话已经是假的**。正是本仓「语义上必须相等的两个值要派生、不要各写一份」那条的实例。要么让它真的从 `REQ_LOG_CAP` 派生，要么把那句「同量级」改成如实说明为什么故意不同。<br>⚠️ **不建议给环加字节预算**（Find 代理提的第二半）：真实量级重算后是 32~65 MB、有界非泄漏、触发前提是用户**主动打开**默认关闭的排障开关；而把最老条目的 trace 置 None 等于**在用户刚打开取证开关时开始丢取证数据**，方向与 `log_cap.rs` 那次提上限的初衷（「上游点名了工具而我们的日志恰好不含那一段」）正相反。在没有一次真实 RSS 观测之前，那是拿确定的取证损失换一个没人报过的内存数字。
- **A7-5**：依赖数组收窄成 `[open]`。菜单开着时 Key 被删导致越界已由 `:120` 的 `if (o)` 兜住。本仓无 jsdom，故只能加源码级判据（照 `modelMappingRows` / `envConflictBanner` 的做法）。
- **A7-6**：参数表加 `--max-columns 400` + `--max-columns-preview`（后者让超长行给前 400 字符预览而不是整行换成一句提示，保住可读性；实测 ripgrep 14.1.1 下 1.4MB 单行文件 stdout 从 1 400 055 B 降到 476 B，且 `path:num:` 前缀仍在、`split_rg_line` 不断）。<br>🔴 `agent_tools.rs` **frozen=949、余量 0**，必须先腾：把 :705-716 六组 `"--glob", "!xxx"` 各并成一行可省 6 行（是删/合并，不是重排）。<br>⚠️ **walk_grep（:861）要另截** —— 它是 rg 起不来时的降级路径，同样整行 push；只加 rg 旗标的话，本机（rg 是 bash function、不在 PATH 上）一条都防不住。
- **A7-7**：**分两步，别一次改完。**<br>① 零风险那半：`:687` 自愈分支里 `payload` 已是死重，建 `plain` 前先 `drop(payload)`（或把首个请求收进内层 scope）。~1 行，不碰缓存注入，直接消掉第四份 —— 而那一刻恰好是「历史最大 + 双份同时在」。<br>② 借用序列化那半**另开一轮**：🔴 Find 代理提的 `Body<'a> { messages: &'a [Value] }` 会**弄坏 Anthropic prompt caching** —— `cache::inject_anthropic_cache`（`cache.rs:56`）签名是 `&mut Value`，在两处**原地改树**（tools 末元素 + 最后一条消息的最后一个 content 块），借用切片做不到。那正是 `payload` 必须是 owned mutable 树的全部理由，而报告的草图从头到尾没提缓存注入。弄错的失效方向**静默**：缓存不命中只表现为账单变贵。<br>session.rs 生产段 756、**未冻结**（900 上限，余量 144），放得下。

精确对应「这个 Key 真的恢复了」；若也按窗口算，「窗口到期后第一次成功」就发不出恢复回执，
而用户手上最后一条正是熔断告警，不给回执会让告警永远悬着。两处口径**不同是设计**，
不是分叉——已在两侧注释互相指认。

**A4-03**：`show()` 失败改落 `warn` 日志。同时推翻既有注释的因果：
`tauri_plugin_notification::init()` 在 `run()` 里**没有 cfg 门**，插件 crate 在
`cargo test` 下照常链接，`#![cfg(not(test))]` 拦不住链接、只拦调用点；临时去掉该 cfg 后
`cargo test --lib` 仍 **580 passed** 不复现启动崩溃。保留 cfg（测试进程不该弹系统框），
但注释改成实测结论，避免下次撞同类崩溃时在错误的一行上找答案。

### 关键链路复审结论

#### 1. contextWindow / 1M：已通过

- 前端存储的始终是最终整数 token 数；单位只影响输入和显示。
- `tokensFromAmount` 用十进制字符串 + `BigInt` 换算，避免 `1.000001M` 的浮点误判；上限与 Rust `u32` 一致。
- 原生 `<input type=number>` 的 `badInput` 单独建模，非法中间态阻止保存，不静默清空旧值。
- 无效模型按 `realName` 记录；模型去重已在手动新增 / 预设导入入口完成；删除模型同步清理无效集合。
- `effective_beta_header` 只对 Anthropic 上游、按本次解析后的真实模型 `contextWindow >= 1_000_000` 追加；流式与非流式共用 `apply_upstream_headers`。
- 客户端原有 beta 头保留且去重；OpenAI 协议不新增 1M beta。
- 桌面端 `supports1m` 只在主 Key 对外名能明确解析到 Mapping/Tier/Native 且窗口有依据时断言；兜底模型不冒充能力。
- Windows/macOS 共用同一 React 前端和 Rust 代理代码，单位输入无需分平台复制。

#### 2. Windows 密钥链：已通过

- 默认模式走 DPAPI；密钥不随配置对象下发。
- 解密缓存由 `set/remove/lock/unlock/三次整库迁移` 全部清空；行为测试覆盖。
- 落盘失败回滚内存；密钥保存先写库、再置 `has_secret`，避免 UI 标记领先密钥库。
- `%APPDATA%` 的 MSIX 虚拟化仍按项目硬规则处理，日志和 MCP 端口的共享判据未被 mac 适配破坏。

#### 3. macOS 密钥链：高风险并发项已修

- 默认模式走 Keychain 托管 32 字节库密钥 + AES-256-GCM。
- 新增 `cached_or_try_init_copy`：Mutex 串行首次成功初始化、锁内二次检查、失败不缓存。
- 32 线程 barrier 测试钉住“初始化只执行一次、所有线程拿同一值”；另测首次拒绝后可重试成功。
- Keychain 真机授权/拒绝路径仍需实际 Mac 验证，报告不把编译通过冒充运行通过。

#### 4. 路径与只读工具：已通过（Unix 补强）

- Windows：硬链接别名枚举，只有存在敏感名字才拒。
- Unix/macOS：标准库不能从 inode 反查所有路径，`nlink>1` fail-closed；已补普通文件放行、硬链接双向拒绝、图片入口复用防线测试。
- macOS 日志走 `~/Library/Logs/SynaRoute`，运行数据/MCP 端口走 `~/Library/Application Support/SynaRoute`；Windows exe 同级判据保留以避 MSIX 虚拟化。
- 三端配置写路径分离，回滚与备份逻辑未发现新的跨平台分叉。

#### 5. 生命周期与托盘：已通过

- Windows `CloseRequested`：阻止退出并隐藏到托盘。
- macOS：图标设置 template，运行状态移到 tooltip；不再用彩色/灰度表达不可见的状态差。
- `Cmd+Q` 绕过 `CloseRequested/ExitRequested`，但 runtime-wry 把 `LoopDestroyed` 映射成 `RunEvent::Exit`，日志与健康态清理仍执行。
- 托盘启停代理复用工具配置写入/还原语义；失败后重建托盘，避免假勾选。
- 自启动由 Tauri 插件适配 Windows Run 键 / macOS LaunchAgent；系统副作用失败与落盘失败均有回滚编排测试。

#### 6. 构建与更新：测试包通过，正式发布未通过

- Windows：NSIS 路径未改，现有部署硬规则仍要求 `tauri build` + 前端 chunk 嵌入判据。
- mac CI：`set -o pipefail` 防 `tail/tee` 吞非零码；`continue-on-error` 后有显式失败汇总步骤。
- `.app` / `.dmg` / updater `.app.tar.gz + .sig` 均有存在性判据；tar 真解一次检查主程序可执行位，避免 upload-artifact 丢权限。
- mac CI 使用临时 updater 私钥，只证明打包链，不能证明真实更新签名；Step Summary 已明示。
- 旧 JIT entitlements 删除是权限收敛：Apple 要求只给实际执行 JIT 的目标开例外，系统 WKWebView 的 WebContent 进程不由宿主 entitlement 授权。
