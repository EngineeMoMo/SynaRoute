### 关键链路复审结论

#### 1. contextWindow / 1M：已通过

- 前端存储的始终是最终整数 token 数；单位只影响输入和显示。
- `tokensFromAmount` 用十进制字符串 + `BigInt` 换算，避免 `1.000001M` 的浮点误判；上限与 Rust `u32` 一致。
- 原生 `<input type=number>` 的 `badInput` 单独建模，非法中间态阻止保存，不静默清空旧值。
- 无效模型按 `realName` 记录；模型去重已在手动新增 / 预设导入入口完成；删除模型同步清理无效集合。
- `effective_beta_header` 只对 Anthropic 上游、按本次解析后的真实模型 `contextWindow >= 1_000_000` 追加；流式与非流式共用 `apply_upstream_headers`。
- 客户端原有 beta 头保留且去重；OpenAI 协议不新增 1M beta。
- 桌面端 `supports1m` 只在主 Key 对外名能明确解析到 Mapping/Tier/Native 且窗口有依据时断言；兜底模型不冒充能力。
- Windows/macOS 共用同一 React 前端和 Rust 代理代码，单位输入无需分平台复制。

#### 2. Windows 密钥链：已通过

- 默认模式走 DPAPI；密钥不随配置对象下发。
- 解密缓存由 `set/remove/lock/unlock/三次整库迁移` 全部清空；行为测试覆盖。
- 落盘失败回滚内存；密钥保存先写库、再置 `has_secret`，避免 UI 标记领先密钥库。
- `%APPDATA%` 的 MSIX 虚拟化仍按项目硬规则处理，日志和 MCP 端口的共享判据未被 mac 适配破坏。

#### 3. macOS 密钥链：高风险并发项已修

- 默认模式走 Keychain 托管 32 字节库密钥 + AES-256-GCM。
- 新增 `cached_or_try_init_copy`：Mutex 串行首次成功初始化、锁内二次检查、失败不缓存。
- 32 线程 barrier 测试钉住“初始化只执行一次、所有线程拿同一值”；另测首次拒绝后可重试成功。
- Keychain 真机授权/拒绝路径仍需实际 Mac 验证，报告不把编译通过冒充运行通过。

#### 4. 路径与只读工具：已通过（Unix 补强）

- Windows：硬链接别名枚举，只有存在敏感名字才拒。
- Unix/macOS：标准库不能从 inode 反查所有路径，`nlink>1` fail-closed；已补普通文件放行、硬链接双向拒绝、图片入口复用防线测试。
- macOS 日志走 `~/Library/Logs/SynaRoute`，运行数据/MCP 端口走 `~/Library/Application Support/SynaRoute`；Windows exe 同级判据保留以避 MSIX 虚拟化。
- 三端配置写路径分离，回滚与备份逻辑未发现新的跨平台分叉。

#### 5. 生命周期与托盘：已通过

- Windows `CloseRequested`：阻止退出并隐藏到托盘。
- macOS：图标设置 template，运行状态移到 tooltip；不再用彩色/灰度表达不可见的状态差。
- `Cmd+Q` 绕过 `CloseRequested/ExitRequested`，但 runtime-wry 把 `LoopDestroyed` 映射成 `RunEvent::Exit`，日志与健康态清理仍执行。
- 托盘启停代理复用工具配置写入/还原语义；失败后重建托盘，避免假勾选。
- 自启动由 Tauri 插件适配 Windows Run 键 / macOS LaunchAgent；系统副作用失败与落盘失败均有回滚编排测试。

#### 6. 构建与更新：测试包通过，正式发布未通过

- Windows：NSIS 路径未改，现有部署硬规则仍要求 `tauri build` + 前端 chunk 嵌入判据。
- mac CI：`set -o pipefail` 防 `tail/tee` 吞非零码；`continue-on-error` 后有显式失败汇总步骤。
- `.app` / `.dmg` / updater `.app.tar.gz + .sig` 均有存在性判据；tar 真解一次检查主程序可执行位，避免 upload-artifact 丢权限。
- mac CI 使用临时 updater 私钥，只证明打包链，不能证明真实更新签名；Step Summary 已明示。
- 旧 JIT entitlements 删除是权限收敛：Apple 要求只给实际执行 JIT 的目标开例外，系统 WKWebView 的 WebContent 进程不由宿主 entitlement 授权。

### 修复建议

1. **已实施**：macOS Keychain 首次初始化增加 Mutex + 锁内二次检查，失败不缓存。
2. **已实施**：Unix `nlink>1` fail-closed 增加 2 条 mac/Linux 专属行为测试。
3. **已实施**：删除无依据的宿主 JIT entitlements 及 tauri 配置引用。
4. **建议后续**：把 `tokensFromAmount/preferredUnit/amountForUnit` 抽到独立模块，补 Vitest 表格化测试；不阻断当前提测。
5. **正式 mac 发布前必须**：Developer ID 签名 + notarization；使用生产 updater 私钥生成 `.sig` 并生成匹配 `darwin-aarch64` 的 `latest.json`；真机验证安装和更新。
