# 大脑聚合 使用与测试说明

> 一句话：**多个模型并行分析同一个需求 → 汇总 → 由「决策者」综合出最终方案**。用来做代码审查、方案设计、疑难排查等需要多视角的任务。
> 界面文案以中文为准（右上角可切 en）。

大脑聚合有**两条使用通道**，测试时分开看：

| 通道 | 入口 | 谁触发 | 会不会改文件 |
|------|------|--------|-------------|
| **A. 桌面面板** | App「大脑」页 | 你在界面里填 prompt 点运行 | 计划阶段不改；点「确认执行」才按计划写文件 |
| **B. MCP 工具** | Codex/Claude Code 调 `synaroute_ai` | 客户端里调用工具 | **绝不改文件**，只返回建议，由客户端自己改 |

---

## 一、先决条件（两条通道都要）

1. **至少 2 个可用的 Key**（同一个分类下，比如 claude-cli），都填了有效密钥、健康显示 up。
   - 成员和决策者都从这些 Key 里选，所以 Key 得先配好、能用。
2. 打开 App →左侧「**大脑**」页（大脑图标）。
   - 注意：大脑页**顶部有自己的分类切换**（claude-cli / claude-desktop / codex），三个分类的聚合配置**互相独立**。先确认你在对的分类上。

---

## 二、桌面面板配置（对照界面从上到下）

### 1. 启用大脑聚合
最上面的开关「**启用大脑聚合**」打开。（不打开，下方运行面板不出现）

### 2. 参与成员（并行解答）
这些是"并行思考"的模型，多多益善（2~4 个即可测）。
- 点「**添加成员**」→ 先在下拉选一个 **Key** → 再选该 Key 下的一个**模型**（模型是之前在 Key 编辑器里拉取/手填的）。
- 加进来的成员会列出来，带品牌图标 + 健康徽标，可点 ✕ 移除。
- **建议**：加 2 个不同厂商/模型的成员（比如一个 Claude、一个 GLM），多视角效果才明显。

### 3. 决策与汇总
- 「**最终决策者 \***」（必填）：综合所有成员意见、产出最终方案的模型。选一个 Key + 模型。**没配决策者无法开启聚合**（会提示「未配置决策者」）。
  - 建议选一个能力较强的模型当决策者。
- 「**汇总模型**」（选填）：只在下面选「A·压缩汇总」模式时才用到；留空则复用决策者。测试时可留空。

### 4. 聚合策略
- 「**A · 压缩汇总**」：先让汇总模型把各成员答案压缩，再交决策者（**省 token**，成员多/上下文大时用）。
- 「**B · 全量上下文**」：把成员完整答案原样交决策者（**信息最全**，成员少时用）。
- **首次测试建议选 B·全量上下文**，链路最直观。
- 「并发上限」：同时最多几个成员在跑（默认 3，测试保持即可）。
- 「总超时 (ms)」：**单个成员**的调用超时（默认 60000=60s）。注意本轮改过：这是**单成员**上限，不是整轮——一个成员慢不会拖垮已答完的。

### 5. 文件知识检索（选填，但推荐开来测 E-1 完整链路）
打开「**启用文件知识检索**」后，聚合时会从工作目录检索相关文件注入上下文（这样模型能"看到"你的代码）。
- 「**自动跟随最近活动项目**」：
  - **开** → 自动取你在 Claude CLI / Codex 里最近打开的项目目录（下面会显示识别到的目录）。
  - **关** → 手动填「工作目录」（如 `E:\projects\my-app`），或点「浏览…」选，或从「最近使用」里挑。
- 「检索内容 Token 上限」：注入上下文的裁剪上限（默认 50000）。
- **测试建议**：先关自动跟随，手动填一个**小项目**目录（文件少、检索快），好观察。

### 6. 保存
点「**保存聚合配置**」。出现绿色「已保存」即写盘成功（本轮修复：写盘失败会弹红色 toast，不再静默）。

## 三、运行聚合（桌面面板，对应 E-1）

配置区下方、开关打开且配了决策者后，会出现「**运行聚合**」面板：

1. 在输入框填一个需求，例如：
   - `审查这个项目的错误处理是否健壮，指出要改的文件`
   - `这个项目是做什么的？架构上有什么可改进的`
2. 点「**开始**」→ 进入"思考中…"（成员并行跑 → 聚合 → 决策者出计划，**会真实消耗 Key 额度**，等几秒到几十秒）。
3. **成功判据（E-1 核心）**：下方「修改计划」区出现**决策者综合的方案/计划文本**。
   - ⚠️ 这一步就是本轮 P0 修复点：**旧版这里 100% 报错、面板空白**。能看到计划文本 = 修复成功。
4. 若开了检索 + 计划里含要改的文件，可点「**确认执行**」→ 决策者按计划输出完整文件内容并写入工作目录 → 「执行结果」区显示改了哪些文件。
   - 不想写文件就点「取消」。
   - 本轮加固：决策者若想写 `../` 或绝对路径会被**拒绝**（不逃逸工作目录）。

> 想测**成员失败容错**（9.7）：故意把某个成员的 Key 密钥改错，再运行 → 该成员被静默跳过，其余照常出结果。
> 想测**决策者失败**（9.8）：把决策者 Key 改错 → 明确报错（决策者是必需的）。

## 四、MCP 工具通道（对应第 13 组 / C 组）

这条通道是给 **Codex / Claude Code** 用的：它们通过 MCP 调 `synaroute_ai`，触发同一套聚合，但**只返回建议、绝不改文件**。

1. **前置**：设置页打开 MCP 开关（见 `verify-mcp-autostart.sh`）；大脑页把该分类配好（成员+决策者，同上）。
2. **快速验证（不装客户端，直接 curl）**：
   ```bash
   export MCP=http://127.0.0.1:9527/mcp   # 端口以设置页显示为准
   curl -s $MCP -X POST -H "content-type: application/json" -d '{
     "jsonrpc":"2.0","id":1,"method":"tools/call","params":{
       "name":"synaroute_ai",
       "arguments":{"prompt":"这个项目做什么","cwd":"F:/SynaRoute"}}}'
   ```
   **判据**：返回一段 Markdown 分析，末尾带「参与模型 / 决策者 / 检索文件 X 个 / 耗时 Yms」，`isError:false`。
3. **真机接入**：按设置页「配置向导」把 `http://127.0.0.1:端口/mcp` 填进 Codex(`~/.codex/config.toml`) 或 Claude Code 的 MCP 配置，重启客户端 → 它们能看到并调用 `synaroute_ai`。
   - `synaroute_ai` 参数：`prompt`（必填）、`cwd`（项目绝对路径，强烈建议传）、`category`（用哪个分类的配置，默认 claude-cli）、`languageHint`（回答语言 zh/en）。

## 五、最省事的一条测试路径（明天照这个走）

1. claude-cli 分类下确保有 2 个能用的 Key（健康 up）。
2. 大脑页（顶部选 claude-cli）→ 开「启用大脑聚合」。
3. 加 2 个成员（不同模型）。
4. 决策者选一个强模型。
5. 聚合策略选「B·全量上下文」。
6. 检索：关掉自动跟随，手动填一个小项目目录（或先不开检索，纯问答也能测通链路）。
7. 保存 → 绿色「已保存」。
8. 运行面板填 `这个项目是做什么的`（若开了检索就填跟代码相关的）→ 点「开始」。
9. **看到计划文本出现 = E-1 通过。** 想测写文件就点「确认执行」看结果区。
10. （可选）设置页开 MCP → 跑上面的 curl → 看到 Markdown 分析 = MCP 通道通过。

## 六、常见现象与排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 运行按钮点了没反应/面板不出现 | 未开启聚合开关，或没配决策者 | 开开关 + 配决策者 |
| 一直"思考中"很久 | 成员/决策者模型慢，或单成员超时设太长 | 等；或调小「总超时」 |
| 结果只有决策者视角、成员像没参与 | 成员 Key 全部失败/超时，降级为决策者独答 | 查成员 Key 健康、密钥、模型名对不对 |
| 报错提到"决策者" | 决策者 Key 不可用 | 换有效的决策者 Key |
| 开了检索但模型说"没看到文件" | 工作目录填错、或该目录没有相关文件、或没装 ripgrep 走了慢兜底 | 核对目录；装 rg 更快 |
| MCP curl 连不上 | MCP 没开或端口变了 | 跑 `verify-mcp-autostart.sh` |

---

**已知限制（非 bug）**：聚合当前只处理**纯文本**响应；跨协议转换虽已支持工具调用，但聚合成员/决策者调用本身是纯文本，不处理图片等多模态（界面底部有蓝色提示条说明）。
