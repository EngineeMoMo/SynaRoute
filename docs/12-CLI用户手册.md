# SynaRoute CLI 接入用户手册（试用版）

> 适用版本：SynaRoute 0.2.1 · 面向 Claude Code 命令行（`claude`）用户
> 一句话：SynaRoute 在你本机起一个代理，把 `claude` 的请求按你配的多个 Key 做**故障转移 + 模型映射**，一个挂了自动切下一个。

---

## 1. 这是什么，解决什么问题

你有多个 AI 服务的 Key（不同厂商 / 不同中转站），想让 `claude` 命令行：

- **一个 Key 限流/挂了，自动切到下一个**，不用手动改配置；
- **不同厂商模型名对不上**（客户端要 `claude-opus-4-x`，上游只认别的名），自动映射；
- 密钥**本地加密存放**，不散落在各处明文配置里。

SynaRoute 就是干这个的：它在 `127.0.0.1` 上开一个本地代理端口，`claude` 把请求发给它，它再按你的规则转发给真正的上游。**只监听本机，不对外**。

---

## 2. 安装

1. 双击 `SynaRoute_0.2.1_x64-setup.exe`，按提示安装（当前用户安装，无需管理员）。
2. 首次运行如提示缺 WebView2，安装包会自动下载安装（Win11 一般自带，无感）。
3. 安装完从开始菜单启动 **SynaRoute**。

> 卸载：控制面板 → 程序 → 卸载，或开始菜单右键卸载，跟普通软件一样。

前置要求：**Claude Code CLI ≥ v2.1.129**（低于此版本 `/model` 选择器不会拉取代理暴露的模型列表）。查看版本：

```bash
claude --version
```

---

## 3. 三步跑起来

### 第 1 步：添加 Key

打开 SynaRoute，进「Claude CLI」分类，点「添加 Key」，填：

- **名称**：随便起，方便你自己认（如 `主力`、`备用`）；
- **厂商 / 协议**：选上游对应的（Anthropic 原生 / OpenAI 兼容 / 自定义）；
- **Base URL**：上游地址（如 `https://api.your-provider.com`）；
- **API 密钥**：你的上游 Key（本地加密存，不进任何明文配置）；
- **模型**：可留空（保存后可自动拉取），或手填上游支持的模型名。

想要故障转移就**多加几个 Key**。上下拖动可调优先级（越靠上越先用）。

### 第 2 步：点「启动」

在顶部状态条点 **启动**（▶）。这一步会：

1. 在 `127.0.0.1` 上开一个代理端口（端口由系统自动分配，每次可能不同）；
2. **自动写入** `~/.claude/settings.json`（原文件会先备份），把 `claude` 指向这个代理。

状态条会显示：`● 运行中`、当前地址 `http://127.0.0.1:<端口>`、以及路由模式图标（单 Key=直连，多 Key=故障转移 + 数字）。地址旁有「复制」按钮。

> 你**不用**手动改任何配置文件——「启动」已经把 `claude` 接好了。

### 第 3 步：正常用 claude

**新开一个终端**（让它读到刚写入的配置），照常用：

```bash
claude
```

`claude` 现在走的就是 SynaRoute 代理。`/model` 里能看到 SynaRoute 暴露的可选模型。

---

## 4. 关于「启动 / 关闭」的几个要点

- **代理不随应用自启**：每次想用，需在 SynaRoute 里点一次「启动」。
- **关窗口 ≠ 退出**：点右上角关闭只是**隐藏到系统托盘**，代理**继续在后台跑**，`claude` 照常能用。想彻底停：右键托盘图标 → 退出。
- **端口是动态的**：每次「启动」端口可能变，但「启动」会自动把新端口写回 `~/.claude/settings.json`，你新开终端即可，无需手动改。

---

## 5. SynaRoute 往 `~/.claude/settings.json` 写了什么

点「启动」后，SynaRoute 会在你的 `~/.claude/settings.json` 里写入这些字段（**改动前会自动备份原文件**）：

| 字段 | 值 | 作用 |
|---|---|---|
| `env.ANTHROPIC_BASE_URL` | `http://127.0.0.1:<端口>` | 把 `claude` 指向本地代理 |
| `env.ANTHROPIC_AUTH_TOKEN` | `synaroute-proxy`（占位） | 代理不校验它，但 CLI 要求存在 |
| `env.CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` | 让 `/model` 去代理拉取可选模型列表 |
| `env.ANTHROPIC_MODEL` + 顶层 `model` | 主 Key 的默认对外模型名 | `/model` 的默认项 |

同时会**删除**旧的 `ANTHROPIC_DEFAULT_HAIKU/SONNET/OPUS_MODEL`（若存在），避免 `/model` 里出现三个同名 Custom 项。三档（Haiku/Sonnet/Opus）由代理内部按规则解析，无需在客户端写死。

> 想看当前实际写入内容：状态条上的「配置预览」按钮（只读，密钥已脱敏）。

---

## 6. 模型是怎么选中的（映射与三档）

`claude` 发来一个模型名（如 `claude-opus-4-x`），SynaRoute 按**优先级从高到低**决定真正发给上游哪个模型：

1. **精确映射**：你为该 Key 配了「客户端名 → 上游真实名」的映射，命中即用（最高优先，你的显式意图永远赢）；
2. **三档匹配**：请求名里含 `haiku`/`sonnet`/`opus` 且你为该 Key 配了对应档位 → 用该档模型；
3. **原生同名**：该 Key 的模型列表里正好有这个名字 → 原样使用；
4. **默认模型**：用该 Key 配的默认模型兜底；
5. **列表第一个**：以上都没有，取该 Key 模型列表的第一个；
6. **透传**：该 Key 没配任何模型 → 原样把请求名发给上游。

**常见坑**：三档优先级高于「原生同名」。如果你给某 Key 设了「三档 Opus = 某模型」，那么**所有**含 `opus` 的请求都会被改写成那个模型，即使该 Key 原生就支持客户端要的名字。**不想要这个改写，就把对应档位留空。**

> 非 `claude*`/`anthropic*` 开头的模型名（如 `grok-4.5`），CLI 会静默过滤掉。SynaRoute 会自动把它们包装成 `claude-synaroute-<原名>` 暴露给 `/model`，转发时再剥掉前缀。所以你在 `/model` 里看到 `claude-synaroute-xxx` 是正常的。

## 7. 故障转移与健康状态

- **多个 Key 时自动故障转移**：主 Key 返回限流/繁忙/错误（HTTP 429/5xx 等）时，自动切到下一个候选 Key 重试，`claude` 侧无感。运行日志里能看到「转移」记录。
- **健康检查**：后台按设置的间隔（默认 60 秒）探测各 Key 可达性，在列表上显示 `可达 / 不可达` 和延迟。
- **重要**：健康状态**只影响界面展示，不挡路由**。显示「不可达」的 Key 仍会被真实流量尝试——真实请求的连续失败才会触发短暂熔断（自动跳过一小段时间）。所以偶尔看到红色「不可达」不代表不能用。

设置页「调试」区可调：

- **记录调用模型日志**：开启后每次转发都记录「客户端要什么 → 实际发了什么 → 结果」，排查用（默认关）。
- **健康检查用真实请求**：开启后探测会发一个极小的真实请求来判定，更贴近实际业务；代价是被限流(429)/繁忙(503)的 Key 也会显示「不可达」，看着扎眼但**不影响实际转发**。想少点红字可关掉它，回到轻量连通探测（能连通即算可用）。

## 8. 常见问题（FAQ）

**Q：`/model` 里看不到我的模型？**
A：确认 ①CLI ≥ v2.1.129；②SynaRoute 已「启动」；③该 Key 配了模型（或已成功拉取）；④你是在**点启动之后新开的终端**里跑 `claude`。

**Q：`claude` 报连接被拒 / connection refused？**
A：SynaRoute 没在跑。回 SynaRoute 点「启动」，然后新开终端。注意关窗口只是隐藏到托盘，但若从托盘「退出」了就得重新启动。

**Q：某模型总是 503 / 502 / 429？**
A：那是**上游**返回的（不是 SynaRoute）。检查该 Key 对应上游是否过载/限流/账号问题。多配几个 Key 可让故障转移兜底。

**Q：请求名被改成了我没预期的模型？**
A：多半是该 Key 的「三档」某档配了值（见第 6 节的坑）。把不想要的档位留空即可。

**Q：想临时不用 SynaRoute，直连官方？**
A：SynaRoute 改动前备份了你的 `~/.claude/settings.json`。可从备份恢复，或手动删掉写入的 `ANTHROPIC_BASE_URL` 等字段。

**Q：密钥安全吗？**
A：密钥本地加密存储（`%APPDATA%\SynaRoute\secrets.enc`），不写进 `settings.json`（那里只有占位 token）。配置预览里密钥也做了脱敏。

## 10. 试用反馈请带上这些

遇到问题反馈时，尽量附上：

1. 现象（`claude` 的报错原文 / 截图）；
2. SynaRoute **运行日志**里相关的几行（尤其是 `请求` / `故障转移` / `健康检查` 分组）；
3. 涉及哪个 Key（名称即可，别发密钥）、哪个模型名。

> 反馈中**不要**粘贴任何真实密钥。日志和配置预览已做脱敏，但手动复制时请自行注意。
