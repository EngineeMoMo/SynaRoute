# Codex 跨机器 401：配置根目录分叉复盘

## 结论

用户提供的另一台机器中，`config.toml` 表面上已经写对：

- 顶层 `model_provider = "synaroute"`
- `model_providers.synaroute.base_url = "http://127.0.0.1:47101/v1"`
- bearer 与 `requires_openai_auth = true`
- `model_catalog_json` 指向 SynaRoute 的模型目录
- `[features] remote_compaction_v2 = false`

但仍收到 `401 Incorrect API key provided: SEE-SYNA...`，URL 为 `https://api.openai.com/v1/responses`。
这证明**不能再把 `remote_compaction_v2` 当成唯一绕过路径**。

两路独立取证确认的确定漏洞是：

- [tools/codex.rs](../src-tauri/src/tools/codex.rs) 原先的 `config_path()` 固定用
  `dirs::home_dir()/.codex/config.toml`，完全不读取 `CODEX_HOME`。
- Codex 自己会读取 `CODEX_HOME`；同仓 [workdirs.rs](../src-tauri/src/workdirs.rs) 的
  `codex_sessions_dir()` 已经按该变量取路径，说明仓库内部存在两套不一致的 Codex 根目录语义。
- `auth_path()`、`codex_catalog::catalog_path()`、MCP 注册、模型选择、漂移检测与还原链都继承
  `config_path()`，因此可能整体写错目录。
- SynaRoute 写默认目录 A，Codex 从 `$CODEX_HOME` 目录 B 读取时，B 缺少 provider，Codex
  回落官方端点，并将 B 的 `auth.json` 中占位符发给 OpenAI，产生用户的 401。

## 已实施修复

新增 [codex_paths.rs](../src-tauri/src/tools/codex_paths.rs)，提供唯一 `codex_home()`：

- `CODEX_HOME` 存在时优先使用；
- 空串、相对路径直接返回错误，**不退回默认目录**；
- 未设置时才使用 `dirs::home_dir()/.codex`；
- `config_path()`、auth、catalog 等调用统一经此路径。

同时保留 auth.json 的可逆策略与 `requires_openai_auth = true`，不删除或覆盖用户真实 OAuth/API
key；不使用代理层拦截，因为绕过请求根本不经过本地 listener。

`remote_compaction_v2 = false` 仍保留为已知功能的缓解，但发布文案不再声称它能覆盖所有平台/后台
路径。`--profile` 旁路与未来/改名的 Codex 平台功能仍需要真实版本探针；不能凭静态配置伪造完整保证。

## 测试与真机判据

- `codex_paths` 单元测试覆盖：绝对路径、未设置、空串、相对路径；
- 使用真实 Codex 隔离目录：设置 `CODEX_HOME` 后接入，确认 config/auth/catalog/MCP 全部写入该目录；
- 确认正常 Responses 请求到 `127.0.0.1:<port>`，不再到 `api.openai.com`；
- 在另一台机器上安装后重新接入、重启 Codex，检查 `CODEX_HOME` 下配置与普通请求；
- 触发自动压缩、remote control、websocket/remote models 等平台功能，若仍绕过 provider，必须在发布说明中明确边界，而不能宣称代理可以拦截。
