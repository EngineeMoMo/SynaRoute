# Claude Desktop 跳过登录页功能测试计划

## 🎯 测试目标
验证启用 SynaRoute 后，Claude Desktop 是否能跳过 get-started 登录页，直接进入主界面。

---

## ✅ 前置条件检查（已完成）

### 1. **SynaRoute 配置档已写入** ✅
   - **路径**: `%LOCALAPPDATA%\Claude-3p\configLibrary\00000000-0000-4000-8000-000053796e61.json`
   - **Gateway**: `http://127.0.0.1:47102`
   - **模型列表**: 
     - claude-opus-4-7 (isFamilyDefault: true, anthropicFamilyTier: opus)
     - claude-opus-4-8 (anthropicFamilyTier: opus)
     - claude-opus-5 (anthropicFamilyTier: opus)
   - **关键字段**: 包含 `anthropicFamilyTier` 和 `isFamilyDefault` ✅

### 2. **SynaRoute 进程可运行** ✅
   - 可执行文件: `F:\soft\SynaRoute\synaroute.exe`
   - 配置已加载（15 个 Key, 6 个 vendor）

### 3. **当前激活状态**
   - `_meta.json` 的 `appliedId` 当前指向: `00000000-0000-4000-8000-000000157210` (CC Switch)
   - **需要切换到 SynaRoute 才能测试**: `00000000-0000-4000-8000-000053796e61`

## 🧪 完整测试步骤

### 第一步：启动 SynaRoute 代理

1. **启动 SynaRoute 应用**
   ```bash
   # 直接运行（或从开始菜单/快捷方式启动）
   F:\soft\SynaRoute\synaroute.exe
   ```

2. **在主界面找到 "claude-desktop" 分类**
   - 点击左侧导航栏或顶部分类切换

3. **点击 "启动代理" 按钮**
   - 通常在页面右上角或底部操作区
   - 应该看到按钮变为 "停止代理"

4. **验证端口监听**
   ```bash
   netstat -ano | findstr "47102"
   # 预期输出：TCP    127.0.0.1:47102    0.0.0.0:0    LISTENING    <PID>
   ```

5. **验证代理响应**
   ```bash
   curl -X GET http://127.0.0.1:47102/v1/models -H "Authorization: Bearer test"
   # 预期：返回模型列表 JSON
   ```

---

### 第二步：接入 Claude Desktop

1. **在 SynaRoute 的 "claude-desktop" 分类页面**
   - 确保代理已启动（上一步完成）

2. **点击 "接入" 按钮**
   - 通常在右上角或页面底部
   - 操作说明：
     - 该操作会将 `_meta.json` 的 `appliedId` 切换到 SynaRoute
     - 会备份原配置为 `*.synaroute.bak`
     - 桌面端会自动检测配置变更并重载

3. **应该看到成功提示**
   - "接入成功" 或类似提示

4. **验证配置已切换**
   ```bash
   cat "%LOCALAPPDATA%\Claude-3p\configLibrary\_meta.json"
   ```
   
   **预期输出**：
   ```json
   {
     "appliedId": "00000000-0000-4000-8000-000053796e61",
     "entries": [
       {
         "id": "00000000-0000-4000-8000-000053796e61",
         "name": "SynaRoute"
       },
       {
         "id": "00000000-0000-4000-8000-000000157210",
         "name": "CC Switch"
       }
     ]
   }
   ```
   
   ⚠️ **关键**：`appliedId` 必须是 `...53796e61`（SynaRoute），不是 `...157210`（CC Switch）

---

### 第三步：重启 Claude Desktop

1. **完全关闭 Claude Desktop**（不是最小化到托盘）
   - **方法 1**：右键任务栏/托盘图标 → 点击 "退出"
   - **方法 2**：任务管理器中找到 `Claude.exe` → 结束任务
   - **方法 3**：Alt+F4（需要窗口在前台）

2. **验证进程已关闭**
   ```bash
   tasklist | findstr /i "claude"
   # 应该没有 Claude.exe 进程，或只剩下无关进程
   ```

3. **重新启动 Claude Desktop**
   - 从开始菜单或桌面快捷方式启动
   - 或直接运行：`"%LOCALAPPDATA%\Programs\Claude\Claude.exe"`

---

### 第四步：验证跳过登录页 ✨

#### ✅ **预期结果（成功）**：

1. **应用启动后直接进入主界面**
   - 看到项目列表 / 会话列表 / 欢迎页面
   - **不显示** get-started 登录页（不要求输入 API key 或登录 Anthropic 账号）

2. **模型选择器显示模型列表**
   - 点击模型选择器（通常在左下角或输入框上方）
   - 应该能看到：
     - claude-opus-4-7
     - claude-opus-4-8
     - claude-opus-5

3. **能正常创建会话并发送消息**
   - 创建新会话
   - 发送测试消息："你好"
   - 预期：收到正常响应（来自 SynaRoute 代理的上游 Key）

4. **检查请求是否走代理**
   - 在 SynaRoute 的 "请求日志" 页面
   - 应该能看到刚才的请求记录

#### ❌ **失败症状（如果出现，说明有问题）**：

1. **显示 get-started 登录页**
   - 要求登录 Anthropic 账号
   - 或要求输入 API key

2. **模型选择器为空**
   - 点击模型选择器，没有任何模型
   - 或显示 "No models available"

3. **创建会话时报错**
   - 错误信息：`ModelsNotDiscoveredError`
   - 或 "Unable to connect to inference gateway"

---

## 🔍 故障排查指南

### 问题 1：仍然显示 get-started 登录页

#### 排查步骤：

1. **检查配置激活状态**
   ```bash
   cat "%LOCALAPPDATA%\Claude-3p\configLibrary\_meta.json"
   ```
   - **检查点**：`appliedId` 必须是 `00000000-0000-4000-8000-000053796e61`
   - **如果不是**：说明「接入」操作未成功，需要重新在 SynaRoute 中点击「接入」

2. **检查代理是否运行**
   ```bash
   # 检查端口监听
   netstat -ano | findstr "47102"
   
   # 测试代理响应
   curl -X GET http://127.0.0.1:47102/v1/models -H "Authorization: Bearer test"
   ```
   - **检查点**：端口必须在监听，curl 必须返回模型列表
   - **如果失败**：在 SynaRoute UI 中点击「启动代理」

3. **检查配置档内容**
   ```bash
   cat "%LOCALAPPDATA%\Claude-3p\configLibrary\00000000-0000-4000-8000-000053796e61.json"
   ```
   - **检查点**：
     - `inferenceModels` 数组不能为空
     - 每个模型必须包含 `anthropicFamilyTier` 字段
     - 至少一个模型有 `isFamilyDefault: true`
   - **如果缺失这些字段**：说明配置档版本过旧，需要重新「接入」

4. **检查桌面端日志**
   ```bash
   # 打开日志目录
   explorer "%LOCALAPPDATA%\Claude-3p\logs\"
   
   # 查看最新日志文件
   # 搜索关键词：ModelsNotDiscovered, gateway, inferenceModels
   ```

---

### 问题 2：模型选择器为空

**根因**：桌面端认为没有可用模型

#### 排查步骤：

1. **检查配置档中的模型名是否合规**
   - 桌面端对模型名有严格过滤（硬编码白名单）
   - 不合规的模型名会被忽略
   - **合规格式**：`claude-{family}-{version}`
   - **不合规示例**：`glm-4.6`, `gpt-5.5`, `custom-model`

2. **验证至少有一个合规模型**
   ```bash
   cat "%LOCALAPPDATA%\Claude-3p\configLibrary\00000000-0000-4000-8000-000053796e61.json" | findstr "claude-"
   ```
   - 应该能看到至少一个以 `claude-` 开头的模型

3. **检查 SynaRoute 中的主 Key**
   - 桌面端分类的主 Key 必须有可用模型
   - 在 SynaRoute UI 中查看主 Key（带 ⭐ 标记）
   - 确保主 Key 有至少一个 `claude-` 开头的模型

---

### 问题 3：代理响应超时或连接失败

#### 排查步骤：

1. **检查防火墙**
   ```bash
   # 临时关闭 Windows 防火墙测试
   # 或添加规则允许 127.0.0.1:47102
   ```

2. **检查 SynaRoute 主 Key 健康状态**
   - 在 SynaRoute UI 中查看主 Key 的健康状态
   - 如果是 "down"，切换到健康的 Key

3. **检查上游 API 可达性**
   - 在 SynaRoute 的测试页面手动发送请求
   - 或命令行测试：
     ```bash
     curl -X POST http://127.0.0.1:47102/v1/messages ^
       -H "Authorization: Bearer test" ^
       -H "Content-Type: application/json" ^
       -H "anthropic-version: 2023-06-01" ^
       -d "{\"model\":\"claude-opus-4-7\",\"max_tokens\":100,\"messages\":[{\"role\":\"user\",\"content\":\"Hi\"}]}"
     ```
