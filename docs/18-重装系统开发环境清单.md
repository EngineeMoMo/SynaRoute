## 0. ⚠️ 重装**之前**必须先备份（丢了不可再生）

| # | 东西 | 位置 | 丢了会怎样 |
|---|---|---|---|
| 1 | **Tauri 更新签名私钥** | `~/.tauri/synaroute.key` + `.key.pub` | **最严重**。它不在 git 里。丢了以后所有已发版本的在线更新永久失效（新私钥签的包，老客户端验签不过），只能让全部用户手动重装 |
| 2 | 未提交的代码 | 本仓库工作区（**当前有 63 个改动文件、0 个未推送 commit**） | 代码丢失。**先 commit + push 再重装** |
| 3 | Claude 记忆与配置 | `C:\Users\mhm29\.claude\`（含 `CLAUDE.md`、`projects\E--workCode-ccCode-SynaRoute\memory\`）、`C:\Users\mhm29\.claude.json`（MCP 配置） | 项目上下文、踩坑记忆、MCP 服务器配置全丢，接手成本大增 |
| 4 | `config.json` | `%APPDATA%\SynaRoute\config.json` | Key 的名称/base_url/映射/优先级等元数据丢失（这是普通 JSON，**可以搬**） |
| 5 | API 密钥原文 | 只在你自己手里 | 见下 |

**不用备份、也搬不过去的**：`%APPDATA%\SynaRoute\secrets.enc`。它由 Windows DPAPI 加密、
绑定当前用户账户，**跨机/重装后解不出来**。新系统上必须重新录入密钥，
或用「从 cc-switch 导入」重导（前提是新系统也装了 cc-switch 并有它的 `~/.cc-switch/cc-switch.db`）。

> 想让密钥能跟着走：重装前用设置页的**「导出配置（含密钥）」**，设一个口令。
> 那条路径是 Argon2id + AES-GCM 口令信封，刻意做成不依赖 DPAPI，正是为迁移场景。
> 导出文件里**不含**端口/日志目录/MCP 注册态（属本机运行态）。

备份落盘位置建议：非系统盘（`F:\` / `E:\`）或外部盘。别放桌面、别放 `%APPDATA%`。

（本项目取 GitHub token 靠它，`credential.helper=manager`）。

装完配置身份（本机原值）：

```bash
git config --global user.name "莫海明"
```

```bash
git config --global user.email "mhm292117@163.com"
```

### 2.2 VS Build Tools 2022（**先装这个，再装 Rust**）

下载 [Build Tools for Visual Studio 2022](https://visualstudio.microsoft.com/downloads/#build-tools-for-visual-studio-2022)，
安装时勾选 **「使用 C++ 的桌面开发」（Desktop development with C++）** 工作负载。
它会带上 MSVC 编译器 + Windows 10/11 SDK，两个都要。

装的是 Build Tools 就够，不需要完整 Visual Studio IDE（本机装的正是 BuildTools，
路径 `C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools`）。

判据：

```bash
ls "/c/Program Files (x86)/Microsoft Visual Studio/2022/BuildTools/VC/Tools/MSVC"/*/bin/Hostx64/x64/cl.exe
```

### 2.3 Rust

装 [rustup](https://rustup.rs/)，默认工具链选 **stable-x86_64-pc-windows-msvc**（不要 gnu）。

```bash
rustup default stable-x86_64-pc-windows-msvc
```

```bash
rustup component add clippy rustfmt
```

本项目 `Cargo.toml` 声明 `rust-version = "1.77"`，实测跑在 1.97.0。仓库里**没有**
`rust-toolchain.toml`，所以版本由本机默认工具链决定 —— 用当前 stable 即可。

判据：`rustup component list --installed` 里能看到 `clippy-` 与 `rustfmt-`。

### 2.4 Node.js（走 nvm-windows，本机原方案）

装 [nvm-windows](https://github.com/coreybutler/nvm-windows/releases)。本机布局（沿用可省事）：

| 项 | 本机值 |
|---|---|
| nvm 自身 | `F:\nvm` |
| node 安装位（`NVM_SYMLINK`） | `F:\nvm4w\nodejs` |
| npm 全局 prefix | `F:\nodejs\node_global` |
| 已装版本 | 22.23.0（当前用）、20.20.0 |

```bash
nvm install 22.23.0 && nvm use 22.23.0
```

### 2.5 ⚠️ PATH 环境变量（本机踩过坑，务必照做）

**历史事故**：用户 PATH 里那一段本该是 `F:\nodejs\node_global`，被写成了**裸相对路径
`node_global`**，导致 `claude` 等全局命令全部「不是内部或外部命令」。

所以新系统上配 PATH 时：

1. `npm i -g` 的垫片目录必须写**绝对路径** `F:\nodejs\node_global`（若沿用本机 prefix）。
2. 用户 PATH（`HKCU\Environment`）类型是 `REG_EXPAND_SZ`，里面含 `%NVM_HOME%`、
   `%NVM_SYMLINK%`、`%PyCharm%` 这类未展开变量。**若要程序化改 PATH，用 `reg add` 保留类型，
   绝对不要用 `setx`** —— setx 会展开变量并把类型降级成 `REG_SZ`，把这些引用全破坏掉。
   手改就用图形界面「编辑账户的环境变量」。
3. 改完关掉所有终端，**开新终端**再验证（PATH 不会热更新到已开的窗口）。

判据：新开 CMD 里 `claude --version` 有输出。


```bash

```

桌面应用和官网是**两套独立的 npm 工程**，`site/` 那份别忘了。

### 3.3 首次编译（会比较久）

```bash

```

```bash

```

### 3.4 还原签名私钥

把第 0 节备份的 `synaroute.key` / `synaroute.key.pub` 放回 `~/.tauri/`（即
`C:\Users\<你>\.tauri\`）。公钥指纹应为 `1F6689C022960775`，与 `tauri.conf.json` 里
`plugins.updater.pubkey` 配对。

发版前需要设环境变量（签名口令为空）：

```bash
export TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.tauri/synaroute.key)"
```

**没设它就构建 → 产物无签名 → updater 验签失败**，且这个失败不会在构建时报错。

### 3.5 MCP 服务器配置

| 服务器 | 类型 | 说明 |
|---|---|---|
| `codegraph` | stdio，`codegraph serve --mcp` | 本项目 CLAUDE.md 指定的结构化检索，**建议恢复** |
| `synaroute` | http，`http://127.0.0.1:9530/mcp` | 本项目自己的 MCP（跑起来才通），可选 |

`.codegraph/` 索引目录不在 git 里，新机器上首次需要建索引：

## 5. 重装后仍然成立的三条陷阱（别在新系统上重踩）

1. **MSIX AppData 虚拟化**（本项目最大惨案）。Claude 桌面应用是 MSIX 包，
   它及其派生的一切子进程读写 `%APPDATA%\SynaRoute\*` 会被透明重定向到包内私有副本，
   与用户双击 exe 看到的**真实文件是两个平行宇宙**。速查判据：
   ```bash
   ls -d "$LOCALAPPDATA/Packages/Claude_pzs8sxrjxfjjc/LocalCache/Roaming/SynaRoute"
   ```
   不存在 → 你读的是真实文件；存在 → 结论不可信，需用计划任务逃逸包身份。
   完整复盘见 [11-MSIX虚拟化踩坑复盘.md](11-MSIX虚拟化踩坑复盘.md)。
2. **`secrets.enc` 绑账户**，重装后旧文件解不出（见第 0 节）。
3. **NSIS 安装器至今未被验证过能装成** —— 静默安装 `/S` 在旧机器上卡死过两次，
   此前所有部署都是绕过安装器直接覆盖 exe。重装后若要验证安装器，那是第一次真实验证。
