# 深链接一键导入（`synaroute://`）

让网页（如自建 sub2api / NewAPI 面板）加一个「导入到 SynaRoute」按钮，点一下就唤起
SynaRoute、弹确认框、把该站的**分类 + 端点 + 密钥**导入成一条 Key。对标 cc-switch 的
「导入到 CCS」（`ccswitch://`），形态刻意对齐以降低网页侧改造成本。

## 两半：网页发链接 + 客户端收链接

- **客户端侧（本仓已实现）**：SynaRoute 注册了系统级 `synaroute://` 协议。收到链接后解析、
  弹确认框，用户确认才落盘。绝不静默导入（URL 谁都能构造，见「安全」）。
- **网页侧（你自己改）**：构造一条 `synaroute://` URL 并打开它（`window.location` 或隐藏
  iframe）。本文档给出格式与最小示例。

## URL 格式

```
synaroute://v1/import?resource=provider&category=<分类>&name=<名字>
  &protocol=<协议>&endpoint=<端点>&apiKey=<base64密钥>
  &defaultModel=<默认模型>&timeoutMs=<毫秒>
  &opusModel=<...>&sonnetModel=<...>&haikuModel=<...>&fableModel=<...>
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `resource` | 是 | 固定 `provider`（暂只支持导入 provider） |
| `endpoint` | 是 | Base URL（http/https）。支持逗号分隔多个，**只用第一个**，其余仅在确认框注明 |
| `apiKey` | 否 | **base64 编码**的密钥（见下）。不带则导入后需在客户端手填 |
| `category` | 否 | `claude-cli` / `claude-desktop` / `codex`。不带则确认框让用户选 |
| `protocol` | 否 | `anthropic` / `openai_chat`（别名 `openai`）/ `openai_responses`。不带则确认框让用户选 |
| `name` | 否 | Key 名字，缺省「导入的 Key」 |
| `opusModel` / `sonnetModel` / `haikuModel` / `fableModel` | 否 | 三档/Fable 档映射的真实模型名 |
| `defaultModel` | 否 | 兜底默认模型。中转站每条 Key 常只服务一个模型，带上它导入后即可直接用，不必再手填；缺省则走「三档 → 首个模型 → 透传」兜底链 |
| `timeoutMs` | 否 | 请求超时（毫秒，正整数）。缺省用全局默认 30000ms；推理类中转常需更长（如 `120000`）。非数字/0 会被整条拒绝 |

- **host 必须是 `v1`**（协议版本），**path 必须是 `/import`**。
- `apiKey` 用 base64：标准或 URL-safe 均可，缺 padding 也认；URL 里 `+` 若被转成空格也能还原。
  建议直接 URL-safe base64 + `encodeURIComponent`。
- 所有参数值都要 `encodeURIComponent`（端点含 `:///`、密钥 base64 可能含 `+/=`）。

## 网页侧最小示例

```html
<button id="import-syna">导入到 SynaRoute</button>
<script>
document.getElementById("import-syna").addEventListener("click", () => {
  const apiKey = "sk-你的密钥";
  const params = new URLSearchParams({
    resource: "provider",
    category: "claude-cli",
    name: "我的中转站",
    protocol: "openai_responses",
    endpoint: "https://your-relay.example.com/v1",
    // base64（URLSearchParams 会顺带 URL 转义）
    apiKey: btoa(apiKey),
    opusModel: "glm-4.6",
  });
  window.location.href = "synaroute://v1/import?" + params.toString();
});
</script>
```

未安装 SynaRoute 时点击通常无反应（或浏览器提示找不到应用），属正常。

## 用户会看到什么

点击后 SynaRoute 被唤起并置前，弹出确认框，逐项列出：名字、**端点域名**（让用户核对密钥去向）、
分类、协议、是否带密钥、以及「导入后即启用」提示。用户点「导入」才落盘；点「取消」什么都不写。
分类/协议若 URL 没带，确认框里是下拉，选齐才能点「导入」。

## 🔴 安全

- 深链接携带**明文密钥**，且**任何网页都能构造** `synaroute://` URL 打给本机。因此 SynaRoute
  **必弹确认框**、绝不静默导入；确认框显示端点域名，防钓鱼站诱导导入一个把密钥转走的端点。
- 密钥只在客户端后端内存里待过：确认框预览**不含密钥**（只显示「已带入 / 未带入」），
  密钥不进任何事件、日志。
- 主口令锁定时导入会失败并提示先解锁，不会把密钥丢在半路。
