# 开发规格：`synaroute://` 深链接一键导入

> 交给开发者的自包含规格。目标：网页上一个「导入到 SynaRoute」按钮，点一下唤起
> SynaRoute → 弹确认框 → 用户确认后把该站的**分类 + 端点 + 密钥**导入成一条 Key。
> 对标 cc-switch 的「导入到 CCS」（`ccswitch://`）。

---

## 1. 需求

**用户故事**：我在中转站网页（如 sub2api / NewAPI 面板）看到一条我的 Key，点「导入到
SynaRoute」，SynaRoute 弹出确认框列出要导入的内容，我点确认，这条 Key 就出现在对应分类里、
密钥也带好了，不用手动去新建、填 baseUrl、填密钥。

**这个功能由两半组成，缺一不可**：

| 半 | 谁做 | 产物 |
|---|---|---|
| A. 客户端接收 | SynaRoute（本仓） | 注册系统协议 `synaroute://`、收到链接弹确认框、落盘 |
| B. 网页发送 | 中转站网页 | 一个按钮，构造并打开 `synaroute://…` URL |

两半通过一个**URL 协议契约**（第 3 节）解耦。各自独立开发，只要都遵守这个契约。

**验收标准（端到端）**：
1. 装了 SynaRoute 后，网页点按钮 → SynaRoute 被唤起并置前。
2. 弹出确认框，正确显示名字 / 端点域名 / 分类 / 协议 / 是否带密钥。
3. 点「导入」→ Key 出现在对应分类、密钥可用（能发出一次成功请求）。
4. 点「取消」→ 什么都不写。
5. 分类/协议 URL 没带时，确认框用下拉让用户补，选齐才能导入。
6. **冷启动**（SynaRoute 没开时点链接）与**已运行**两种情形都能到确认框。
7. 主口令锁定时导入报「请先解锁」，不静默丢密钥。

---

## 2. 🔴 安全约束（不是可选项，是这个功能的核心）

深链接携带**明文密钥**，且**任何网页/任何人**都能构造一条 `synaroute://` URL 打给本机。
因此以下是硬约束：

1. **绝不静默导入**。收到链接**必须**弹确认框，只有用户当场点确认才落盘。
2. **确认框必须显示端点域名**（host），让用户看清密钥会被发去哪 —— 防钓鱼站诱导用户导入一个
   把密钥转走的恶意端点。
3. **密钥不进任何可分享的地方**：不进事件流、不进日志、不进确认框的往返载荷（确认框预览只显示
   「已带密钥 / 未带」，不显示密钥本身）。密钥只在客户端后端内存里短暂停留。
4. **解析失败/字段非法一律整条拒绝**，不落半条脏数据。
5. 导入的 Key 默认**启用**（会进故障转移候选池）—— 确认框要注明这一点。

---

## 3. URL 协议契约（A 与 B 的唯一接口）

```
synaroute://v1/import?resource=provider&category=<cat>&name=<name>
  &protocol=<proto>&endpoint=<url>&apiKey=<base64>
  &defaultModel=<m>&timeoutMs=<ms>
  &opusModel=<m>&sonnetModel=<m>&haikuModel=<m>&fableModel=<m>
```

- **scheme** 必须是 `synaroute`
- **host** 必须是 `v1`（协议版本；将来加版本在此显式放行）
- **path** 必须是 `/import`

| 参数 | 必填 | 取值 / 说明 |
|---|---|---|
| `resource` | 是 | 固定 `provider` |
| `endpoint` | 是 | Base URL（http/https）。逗号分隔多个时**只用第一个**，其余仅在确认框注明 |
| `apiKey` | 否 | **base64 编码**的密钥。不带则导入后需在客户端手填 |
| `category` | 否 | `claude-cli` / `claude-desktop` / `codex`。不带 → 确认框让用户选 |
| `protocol` | 否 | `anthropic` / `openai_chat`（别名 `openai`）/ `openai_responses`。不带 → 确认框让用户选 |
| `name` | 否 | Key 名字，缺省用「导入的 Key」 |
| `defaultModel` | 否 | 兜底默认模型（`default_model`）。中转站单模型 Key 带上它导入即可用；缺省走三档/首个兜底 |
| `timeoutMs` | 否 | 请求超时（毫秒，正整数）。缺省全局 30000ms；非数字/0 整条拒绝 |
| `opusModel` `sonnetModel` `haikuModel` `fableModel` | 否 | 三档 + Fable 档映射的真实模型名 |

**编码规则**：
- 所有值都要 `encodeURIComponent`（endpoint 含 `:///`、apiKey base64 可能含 `+/=`）。
- `apiKey` 用 base64：接收方要容错 —— 标准 / URL-safe 都认、缺 padding 补齐、URL 里 `+` 被
  转成空格时能还原。发送方建议直接用 URL-safe base64。

## 4. B 半：网页侧实现

一个按钮，构造 URL 并打开。最小实现：

```html
<button id="import-syna">导入到 SynaRoute</button>
<script>
document.getElementById("import-syna").addEventListener("click", () => {
  const apiKey = "sk-用户这条Key的密钥";
  const params = new URLSearchParams({
    resource: "provider",
    category: "claude-cli",              // 按你的站映射到哪个客户端
    name: "我的中转站",
    protocol: "openai_responses",        // 按你的站的真实协议
    endpoint: "https://your-relay.com/v1",
    apiKey: btoa(apiKey),                // base64；URLSearchParams 会顺带 URL 转义
    opusModel: "glm-4.6",                // 可选：想让三档映射时带
  });
  window.location.href = "synaroute://v1/import?" + params.toString();
});
</script>
```

**注意**：
- 未安装 SynaRoute 时点击通常无反应或浏览器提示找不到应用 —— 属正常，无需处理。
- `btoa` 处理非 ASCII 密钥会抛错；密钥一般是 ASCII，如需保险用 `btoa(unescape(encodeURIComponent(k)))`。
- 不要把密钥打进页面日志 / 上报埋点。

## 5. A 半：客户端（SynaRoute / Tauri v2）实现

> 本仓已实现，以下是**从零复刻**该功能需要做的事，供审阅或移植到其它 Tauri 应用参考。
> 已实现的权威落点见第 8 节。

### 5.1 注册系统协议

- 依赖：`tauri-plugin-deep-link`（`Cargo.toml`）。
- `tauri.conf.json` 的 `plugins` 加：
  ```json
  "deep-link": { "desktop": { "schemes": ["synaroute"] } }
  ```
- capabilities 加权限 `deep-link:default`。

### 5.2 唤起接线（🔴 两条路径必须都覆盖，且同一入口）

深链接到达客户端有两条完全不同的路径，漏一条则那种情形静默不生效：

| 情形 | 路径 |
|---|---|
| 应用**未运行**（冷启动）；macOS 上应用已运行 | `deep-link` 插件的 `on_open_url` 回调 |
| **Windows 上应用已运行** | URL 作为**第二次启动的命令行参数**到达，由 `single-instance` 插件的回调转发 |

**两处都调用同一个处理函数**（避免双路径分叉 —— 一处修了另一处忘了是这类项目的高发 bug）：

```rust
// single-instance 回调里：
.plugin(tauri_plugin_single_instance::init(|app, args, _cwd| {
    show_main_window(app);
    if let Some(url) = args.iter().find(|a| a.starts_with("synaroute://")) {
        handle_deeplink(app, url);   // ← 同一入口
    }
}))
.plugin(tauri_plugin_deep_link::init())

// setup 里：
app.deep_link().on_open_url(move |event| {
    for url in event.urls() {
        handle_deeplink(&h, url.as_str());   // ← 同一入口
    }
});
```

`handle_deeplink` 做三件事：解析 URL 存进待确认槽 → 置前主窗口 → 发事件通知前端弹确认框。
**解析失败只记日志、不打扰用户**（乱构造的链接不该弹一堆报错框）。

### 5.3 解析 + 待确认槽（密钥留在后端内存）

- 解析 URL → 结构体 `ParsedImport`（含明文密钥）。
- 存进**进程内单槽**（`Mutex<Option<ParsedImport>>`，只留最近一次）。
- 只把**不含密钥的预览** `ImportPreview`（密钥仅以 `hasSecret: bool` 体现）暴露给前端。
- 三个 IPC 命令：
  - `deeplink_import_peek() -> Option<ImportPreview>`：确认框挂载时拉预览
  - `deeplink_import_apply(category, protocol) -> String`：确认后落盘，返回新 Key id
  - `deeplink_import_discard()`：取消，丢弃槽

### 5.4 落盘（复用既有写路径，不新造）

`apply` 里组装一条 Key：`id` 留空让后端自生成、`enabled: true`、`priority` 用一个会被
「碰撞顶到队尾」规则处理的值、tier 从 URL 的三档参数映射。然后：
1. 存 Key 本体（走既有的「带回滚、保护运行态字段」的 upsert）。
2. 带了密钥就存密钥（走既有的「先写密钥库成功、再置 `has_secret`」路径）。
   - 🔴 **主口令锁定时密钥写入返 Err → 整个 apply 返 Err**（fail closed），不能吞掉错误
     返回 Ok 让用户以为导进去了。
3. 发配置变更事件，前端刷新 Key 列表。

### 5.5 确认框（前端）

- 订阅后端「导入请求」事件 → 调 `deeplink_import_peek` 拉预览 → 弹框。
- 展示：名字、**端点 host**、分类、协议、是否带密钥、「导入后即启用」提示、多端点注明。
- 分类/协议为空时用下拉让用户选，选齐才允许「导入」。
- 「导入」→ 调 `deeplink_import_apply(category, protocol)` → 成功 toast + 刷新；失败 toast 报错。
- 「取消」→ 调 `deeplink_import_discard`。

## 6. 数据模型

**`ParsedImport`（后端内部，含密钥）**：category(可空) / name / protocol(可空) / base_url /
extra_endpoints / api_key / tier_haiku / tier_sonnet / tier_opus / tier_fable。

**`ImportPreview`（过 IPC，不含密钥）**：category / name / protocol / baseUrl /
extraEndpoints / **hasSecret** / tierHaiku / tierSonnet / tierOpus / tierFable。

分类枚举 `claude-cli | claude-desktop | codex`；协议枚举 `anthropic | openai_chat | openai_responses`。

## 7. 测试计划

**单测（后端解析 + 落盘）**：
- 完整合法 URL → 各字段解析正确，密钥 base64 解回明文，tier 映射到位；没带的 tier 是 None 不是空串。
- category/protocol 缺省 → 留空（不猜）。
- 多端点 → 只取首个，其余进 extra。
- base64 各变体（`+`→空格、缺 padding、URL-safe）都能解回。
- 非法输入全部 Err：错 scheme / 错版本 / 错 path / 缺 resource / 非 provider / 缺 endpoint /
  endpoint 非 http(s) / 未知分类。
- 落盘：确认后 Key 出现在分类、密钥可读回、槽被清空。
- 🔴 **fail closed**：主口令锁定时 apply 返 Err（注入验证：把密钥写入的错误改成吞掉，这条测试必须变红）。

**前端**：确认框在两种预览下渲染正确（字段齐全 / 分类协议为空时出下拉且导入按钮禁用）。

**🔴 真机（唯一裁判，单测替代不了）**：
- 浏览器点一条真链接（或本地 HTML 按钮）→ ①唤起并置前 ②确认框内容对 ③确认后 Key 落地、
  密钥可用 ④锁定态报「请先解锁」⑤**冷启动与已运行两种情形都要各走一遍**（这两条走的是
  5.2 里两条不同代码路径）。

## 9. 刻意不做（避免过度设计，别当遗漏）

- 多 base_url：本应用每条 Key 单端点，只取首个 + 注明。
- 「粘贴链接」输入框兜底：本轮走一键深链接。
- 导入 MCP / prompt / skill（cc-switch 深链接也支持这些）：本轮只做 provider。
