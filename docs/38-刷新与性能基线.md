# 刷新与性能基线

## 状态刷新

分类页的完整加载与事件刷新共用一个串行队列。同一时刻最多一轮分类查询，期间收到的刷新请求合并为下一轮；已被后续请求作废的结果不会写回界面。完整加载的需求不会被轻量刷新覆盖，切换 A → B → A 也不会接收第一次 A 的旧结果。

窗口隐藏时，数据事件只标记待刷新，恢复可见后补查。深链接导入和更新通知仍立即处理。日志只在日志页订阅，不随分类切换读取。页面轮询继续作为丢事件时的兜底。

日志增量接口使用进程 epoch 和递增 revision。新增、折叠、流末用量补记都会更新行版本；淘汰记录通过删除列表同步。行版本和删除历史都有上限，游标超过保留窗口、来自旧进程或大于当前版本时返回完整快照。增量与完整快照均不含请求正文，详情仍按需查询。

## 页面与请求体

首屏路由总览保持直接加载，其余页面和 Key 编辑器按需加载；页面加载提示与错误边界保留。Vite 生产构建输出各页面独立 chunk。

同协议转发借用原始 JSON，只保存可能修改的顶层模型、推理强度、采样参数和输出预算。尝试结束、取消或报错时通过作用域守卫恢复这些字段。需要修改图片等嵌套内容的错误整流先创建独立副本，跨协议转换也使用独立副本，保证后续 Key 收到原始请求。

## 运行性能测量

```powershell
npm run perf -- --output output/performance/baseline.json
npm run perf -- --baseline output/performance/baseline.json --output output/performance/current.json
```

默认使用 release 构建。快速验证可加 `--profile dev`；不同构建模式的结果不能当作性能提升对比。已安装指定 Rust 工具链时可设置 `SYNAROUTE_PERF_TOOLCHAIN`。长跑默认 60 秒，可通过 `SYNAROUTE_PERF_SECS` 调整。

报告保存应用版本、Git 提交、工作区是否修改、CPU、系统、工具链和构建模式；只有环境字段一致才标记为可直接比较。报告脚本失败时不输出伪成功报告。原始日志与 JSON 同目录保存。

测量场景：

- 单 Key 非流式；
- 两个候选 Key 和约 1 MiB 上下文，主 Key 首次成功；
- 主 Key 返回 503，切换备用 Key；
- Chat SSE 转 Anthropic SSE；
- 上游固定延迟 10 毫秒；
- Key 并发槽位饱和后等待释放；
- 1 MiB 请求体深拷贝与借用守卫的独立对照；
- 连续负载 RSS 与长跑稳定性。

请求场景记录响应头与完整响应的 p50/p95/p99，另记录直连相同模拟上游的对照和配对差值。流式响应头时间不是首个模型 token 时间；上游使用固定本地夹具，不能代表真实厂商速度。内存结果受分配器和系统影响，单次增长不等于泄漏。独立请求体测量只反映该步骤开销，不能等同于整个代理的提速比例。

`.github/workflows/performance.yml` 支持手动运行和版本 tag 触发，保存 90 天的性能附件。硬件不固定的 CI 不设置微秒级硬阈值，先保留可比数据；报告解析与比较测试进入日常质量门。
