实现入口：`src-tauri/src/upstream/sse_frames.rs`、`sse_lifecycle.rs`、`proxy/streaming.rs`、`decision/accounting.rs`、`tools/codex_session_page.rs`、`tools/claude_restore.rs`，以及 `src/pages/CodexSessionsPage.tsx`、`src/components/SessionBrowser.tsx`。

关键边界：

- 转换器把成功终态缓冲到 HTTP EOF，防止终态之后的迟到错误被当成成功；上游终态后不关闭连接时，最终收尾会等待 EOF 或既有空闲超时。
- 取消/断开不冒充上游失败，也不按成功衰减健康失败计数。EOF 释放上游和许可后才向下游交付最终帧，避免下游背压占住许可。
- 编码的跨协议 SSE 被明确拒绝。编码直通保留原编码，不能解析其协议终态和用量，也不据此记健康成功。
- 判断服务键使用 `decision:` 加端点与凭据引用的 SHA-256，不把端点或凭据写入展示名。缺 usage 时记录“成本未知”，不编造零费用；本轮未新增判断服务独立自定义价目界面。
- 索引最多保留四个 home，30 秒后或显式刷新重新校验。每次查询仍扫描文件元数据，不是 O(页大小) 的磁盘查询；冷建索引有额外成本。
- Claude 清理只针对已知环境键，保留恢复等待期间的用户改动；journal 的已应用标志和备份 hash 校验覆盖进程崩溃与备份替换窗口。
- Laya Rust 后端只在 Windows x64 作为托管候选；bundle 导入、选择、回滚和 worker 健康检查均在隔离数据目录执行，失败自动回 Python，生产默认仍是 Python 0.3.29。

## 2. Laya 三方案实测

环境：Windows 11 Pro `10.0.26100`，Intel Core Ultra 7 265K（20 核/20 线程），约 31.35 GiB 可见内存。推理统一使用两个 CPU 线程。机器信息见 `output/experiment-machine-2026-11-17.json`。

- 参考 Laya：0.4.35，提交 `b1d656952f0f9581ea691a70cb6f38abf3eb13a9`。
- 模型：相同 multilingual 快照 `7b928d828b7b0e022f929d9bd2e44165aa270148`。使用既有缓存，没有向 C 盘下载新模型；新 ONNX 导出在 D 盘。
- 题集：48 条中英文诊断题，12 条校准、36 条保留题；SHA-256 `96129371ac344e8697431e1abeda521807f3d5149bade1d2a626a73f91339f29`。
- 生产问题和 0.75 阈值固定，没有根据保留题调参。这是新建的可复现题集，不冒充历史文档中未找到原始文件的 18/36 条测试。
- 每题预测三遍；各方案重复三个新进程，Python 两版本交替先后运行。下面采用重复进程中位数，文件系统缓存已预热。

| 方案 | 进程加载中位数 | 热预测中位数 | 首轮峰值内存 | 保留题应升级 12 条：实际升级 | 其余 24 条：误升级 |
|---|---:|---:|---:|---:|---:|
| Python Laya 0.3.29 | 7541.88 ms | 84.42 ms | 2.18 GiB | 7 | 1 |
| Python Laya 0.4.35 | 7474.29 ms | 78.68 ms | 2.17 GiB | 7 | 1 |
| Rust / ONNX | 1624.55 ms | 72.47 ms | ≥0.98 GiB（采样峰值） | 7 | 1 |

全部题目、版本及重复实验的返回分数在四位小数精度上相同。Rust 加载时间降低约 78.5%，热预测降低约 14.2%；Python 新版本在本题集没有判断质量收益。小样本的 7/12 与 1/24 只表示这组诊断题的结果，不是通用路由准确率，也没有测下游答案质量、真实付费模型或 token 节省。

内存口径不同：Python 使用 Windows peak working set，Rust 每 10 ms 采样，因此 Rust 峰值是下界，不能把二者差值当成精确的峰值节省。首个 Python 加载约 12.18 秒受到冷缓存/执行顺序影响，未拿它与后跑方案作性能结论。

Rust 运行文件小，但本次 ONNX 模型接近 PyTorch 模型两倍。以上是本机展开后的文件大小，不是安装器/压缩包下载大小，不包括将来的更新、回滚和离线分发实现。Python 0.4.35 的干净安装解析计划涉及 49 个包，包含 vegaml、cryptography 等新增/升级依赖；实际性能实验以固定源码加载 0.4.35 并复用同一 Python 运行环境，未声称完成 0.4.35 全新安装验收。

导出器的两组 fixture 数值检查通过；36 种 shape/session 组合检查通过，但日志明确写明该 sweep 没有 PyTorch 数值对照。Rust 上游尚不支持 Python 的 histogram binning 和 per-call hooks。

**决定：生产默认仍固定 0.3.29。** Rust/ONNX 已从单个实验 exe 提升为可选托管后端：离线 bundle 带 7 个固定 SHA-256，选择过程原子化，支持健康检查、进程树停止、回滚和 Python 回退；Windows WebView2 已完成真实导入/回滚/48 题推理/停止验收。它仍不是默认后端，也没有把 Windows bundle 宣称为 macOS/Linux 发布包。复现说明见 `scripts/laya/COMPARISON.md`；汇总为 `output/laya-comparison-2026-11-17.json`。
