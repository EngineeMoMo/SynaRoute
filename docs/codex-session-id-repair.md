# 会话同步与工具 ID 修复

会话管理提供三个独立操作：「仅同步 provider」「历史工具 ID 修复」「清理失效条目」。修复 ID 不再附带在 provider 同步中。扫描预览不会改写会话；所有手动写入操作都要求完全退出 Codex/ChatGPT（包括 CLI），完成后再重新打开会话。

## 同步目标与并发保护

- 下拉保留历史 provider 名称作为诊断信息，但只允许选择当前配置中实际存在的 provider 表或内置 `openai`；失效目标禁用。没有配置文件时内置 `openai` 仍可用，配置损坏则拒绝同步。
- 后端不信任下拉结果，会重新验证配置，并在规划完成、每次改写及索引更新前核对配置指纹。变化后停止后续写入；此前已完成的同步仍按原回滚清单处理，不承诺跨文件事务。
- 扫描、修复、同步、还原、删除和索引清理使用同一个基于文件句柄的 OS 维护锁。锁文件保留，进程退出会释放 OS 锁，不靠删除陈旧标记恢复。
- 此锁协调 SynaRoute 实例，不声称能锁住不遵守该协议的其他工具。另有 Codex/ChatGPT 进程检查、文件内容指纹验证及写入时的文件占用保护；请勿同时用其他工具修改会话。
- 长操作移到后台线程；页面展示扫描、核对、同步、索引更新、修复和完成阶段，不用虚构百分比代替真实进度。

## 独立修复流程

1. 点击「扫描并预览」，查看将修改的文件、ID 数量以及不能安全自动修复的项。内部派生会话不纳入计划。
2. 确认后端进程已退出，再点击「确认备份并修复」。只处理该次预览中的可修复文件，不扫描后默默扩大范围。
3. 预览令牌保存在后端内存，10 分钟后过期；重启或另一次扫描使旧令牌失效。执行前逐个验证计划文件的 SHA-256，发现变化则在任何修复写入之前拒绝。
4. 执行阶段再次核对原文指纹；突发错误时停止后续文件，并显示已经完成和未处理的数量及备份路径。已完成的修复不自动撤销，需要重新扫描后继续。

## 边界

- `model_provider` 是同步目标，不是工具的 `namespace`。
- 只规范化已有完整工具调用条目的异常 `id`：`function_call` 使用 `fc_`，`custom_tool_call` 使用 `ctc_`。同文件内的对应条目引用同步更新。
- 保留 `call_id`、工具结果关联、`namespace`、`name`、参数、结果和 reasoning 内容。不对文本做全局替换。
- 同时检查普通 `response_item` 与 `compacted.payload.replacement_history`，包括已归档的用户会话；内部派生会话沿用 provider 同步的排除规则。
- 合法 ID 保持原样。OpenAI → 其他 provider → OpenAI 不会反向改回坏 ID；重复同步不重复备份或改写已修好的正文。
- 缺失调用关联、映射冲突、无法解析或文件占用等问题按文件报告，不再阻断独立的 provider 同步。修复按行流式扫描和改写，不再限制整份文件为 128 MiB；为限制异常输入，单条记录上限为 16 MiB，条目 ID 数上限为 50 万。
- 自动接入同步和停止时的 provider 还原不执行正文修复。

## 备份与回滚

仅对需要修改的文件创建逐字节原文备份，位置是应用数据目录下的 `codex-session-id-backups/<批次 UUID>/<原相对路径>`。结果提示显示实际目录。原文备份与修复临时文件流式写出，备份落盘、指纹核对、临时文件落盘均成功后才替换原文件，保留修改时间。若中途读取或磁盘写入失败，该文件的备份可能不完整，错误信息会明确提示，不能把失败文件的备份当成完整恢复点。

provider 回滚清单与这份正文备份独立。停止代理只按原有逻辑还原 provider，不重新引入坏 ID。如必须撤销正文修复，应退出 Codex，先另行保存当前会话文件，再从对应批次备份恢复；整文件恢复会丢失备份后新增的对话，也会恢复备份时的 provider，不能无条件覆盖。

## 新记录

Chat/Anthropic 转 Responses 的流式工具调用使用独立条目 ID；上游调用关联 ID 不再充当条目 ID。非流式 custom 工具同样使用 `ctc_`。工具命名空间的既有拆分、拼接逻辑不变。

此修复针对 ID 格式错误，不保证服务器端条目引用、加密 reasoning、模型能力或其他跨上游差异均兼容。测试使用本地夹具，不会调用 OpenAI，也不会改写用户真实会话。
