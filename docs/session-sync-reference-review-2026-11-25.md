## 本次修复的实证

新增隔离回归先在旧实现上失败：四条索引中只有一条没有任何存续证据，旧实现却报告四条孤儿。
另外，传入过期首行仍能成功改写文件，可能覆盖新元数据或使用错误的正文偏移。

修复后的清理从文件名识别普通 rollout 与 `.jsonl.zst`，并只读核验所有已发现数据库里的
`threads.id` 和 `local_thread_catalog.thread_id`。数据库引用也可能暂时陈旧，因此采用保守保留；
清理目标仍然只是无任何存续证据的索引。未知 ID、无法解释的记录、空行和保留记录的换行字节均不改写。
扫描深度超限、链接、不可读目录、损坏数据库或未知必需列都会中止清理。

实际替换前再次读取引用集合与源索引；变化则保留原文件与备份并报告重扫。
provider 改写继续只改首行，保留正文及修改时间；Windows 持有拒绝写共享的源句柄，
并在替换前比较复制时的源摘要与当前全文，覆盖“等长改动且 mtime 不变”的情况。
跨文件与跨数据库操作不构成一个全局事务，仍要求手动维护前退出 Codex；不宣称消除了外部进程的全部竞争窗口。
