# 测试用例

真机验收用的测试用例表格，按客户端分成四份。**建议按编号顺序测**：1 是三端通用的基础项，
测完再按你实际要用的客户端挑 2/3/4。

| 文件 | 覆盖范围 |
|---|---|
| `SynaRoute测试用例-1-通用（先测这个）.xlsx` | Key 管理、故障转移、健康检查、代理启停、配置导入导出等三端共通项 |
| `SynaRoute测试用例-2-Claude Code CLI.xlsx` | CLI 特有：`/model` 选择器、三档映射、`settings.json` 接入 |
| `SynaRoute测试用例-3-Claude 桌面端.xlsx` | 桌面端特有：`_meta.json` 接管、对外模型名硬过滤 |
| `SynaRoute测试用例-4-Codex.xlsx` | Codex 特有：`config.toml` + `auth.json` 双文件、推理强度、MCP 工具链 |

## 为什么是 xlsx 而不是 markdown

用例表要在测试过程中**逐行勾选、填实际结果**，表格软件比 markdown 顺手。
代价是 git 里存的是二进制、看不出 diff —— 四份加起来 53 KB，可以接受。

## 刻意没进仓库的两样东西

同目录下原本还有两个文件，都留在本地未提交：

- **`问题.txt`** —— 历次测试记录的问题清单。含本机绝对路径与测试用的中转站域名。
- **`2026-08-02.jsonl`** —— 某次测试的运行日志导出（1.7 MB）。里面 125 条 trace 中有
  **91 条含真实对话正文**（最长单条 2 万字符，含 system prompt）。扫过没有密钥
  （`sk-` / `Bearer` / `x-api-key` 均零命中），但对话内容本身不该进公开仓库。

若日后要往仓库放日志样本，请先剥掉 `trace.requestBody` / `trace.responseBody` 两个字段
—— 那是对话正文所在处（其余字段只是 Key 名、模型名、状态码、延迟，不敏感）。
