# 大脑聚合使用说明

多个模型并行分析同一个需求，汇总后由「决策者」综合出最终方案。适合代码审查、方案设计、疑难排查这类需要多视角的任务。

大脑聚合有**两条使用通道**：

| 通道 | 入口 | 谁触发 | 会不会改文件 |
|---|---|---|---|
| 桌面面板 | 应用的「大脑聚合」页 | 你在界面里填需求点运行 | 出方案阶段不改；点「确认执行」才按计划写文件 |
| MCP 工具 | Codex / Claude Code 调用 `synaroute_ai` | 客户端里调用工具 | **绝不改文件**，只返回建议，由客户端自己改 |

本文讲桌面面板。MCP 通道见 [MCP 接入手册](/zh/docs/mcp)。

## 先决条件

1. **同一分类下至少 2 个可用的 Key**，都填了有效密钥、健康状态正常。成员和决策者都从这些 Key 里选，所以 Key 得先配好。
2. 打开应用左侧的「大脑聚合」页。注意这一页**顶部有自己的分类切换**（Claude CLI / Claude 桌面端 / Codex），三个分类的聚合配置**互相独立**，先确认你在对的分类上。

## 配置（对照界面从上到下）

### 启用大脑聚合

最上面的开关打开。不打开，下方的运行面板不会出现。

### 参与成员

这些是并行思考的模型，2～4 个即可。

- 点「添加成员」→ 先在下拉里选一个 **Key** → 再选该 Key 下的一个**模型**（模型是之前在 Key 编辑器里拉取或手填的）。
- 加进来的成员会列出来，带品牌图标与健康标记，可以移除。
- **建议**：加 2 个不同厂商或不同系列的成员，多视角的效果才明显。

### 决策与汇总

- **最终决策者**（必填）：综合所有成员意见、产出最终方案的模型。选一个 Key 加一个模型。没配决策者无法开启聚合。建议选一个能力较强的模型。
- **汇总模型**（选填）：只在聚合策略选「压缩汇总」时才用到，留空则复用决策者。

### 聚合策略

- **压缩汇总**：先让汇总模型把各成员答案压缩，再交决策者。**省 token**，成员多或上下文大时用。
- **全量上下文**：把成员完整答案原样交给决策者。**信息最全**，成员少时用。首次尝试建议选这个，链路最直观。
- **并发上限**：同时最多几个成员在跑，默认 3。
- **总超时**：**单个成员**的调用超时，默认 60000 毫秒。这是单成员上限而非整轮上限——一个成员慢不会拖垮已经答完的其他成员。

### 文件知识检索（选填）

打开后，聚合时会从工作目录检索相关文件注入上下文，让模型能「看到」你的代码。

- **自动跟随最近活动项目**：打开则自动取你在 Claude CLI / Codex 里最近打开的项目目录（界面会显示识别到的目录）；关闭则手动填写工作目录，或从「最近使用」里挑。
- **检索内容 Token 上限**：注入上下文的裁剪上限，默认 50000。

> 首次尝试建议关掉自动跟随，手动填一个**小项目**目录，文件少、检索快，好观察行为。

### 工具调用（选填，默认关闭）

开启后，参与者可以自己用一组**只读**工具决定看哪些文件：读文件（可指定行区间）、正则搜索、列目录、查符号索引。比前置检索靠关键词猜更准。

**代价是额度消耗明显更高**——每一轮工具调用都要把完整对话历史重发一次。默认关闭就是这个原因。

工具永远只读，不写文件、不执行命令，且限制在工作目录内，凭据类文件一律拒绝读取。

### 保存

点「保存聚合配置」，出现「已保存」提示即写盘成功。写盘失败会明确报错，不会静默吞掉。

## 运行

开关打开且配好决策者后，配置区下方会出现「运行聚合」面板：

1. 在输入框填一个需求，例如「审查这个项目的错误处理是否健壮，指出要改的文件」。
2. 点「开始」，进入思考中——成员并行跑，然后聚合，最后决策者出方案。**会真实消耗 Key 额度**，视模型快慢需要几秒到几十秒。
3. 下方「修改计划」区出现决策者综合的方案文本。
4. 如果开了检索且计划里包含要改的文件，可以点「确认执行」，决策者按计划输出完整文件内容并写入工作目录，「执行结果」区会显示改了哪些文件。不想写文件就点「取消」。

出于安全考虑，决策者若试图写 `..` 或绝对路径会被拒绝，不会逃逸出工作目录。

## 图片输入

通过 MCP 通道调用时可以传图片，用于「这个报错截图是什么问题」这类任务。限制见 [MCP 接入手册](/zh/docs/mcp)。

参与者模型必须支持图片输入。纯文本模型会被上游拒绝，此时失败原因里会附上提示。

## 常见现象与排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 点了运行没反应，或面板不出现 | 未开启聚合开关，或没配决策者 | 打开开关并配置决策者 |
| 一直「思考中」很久 | 成员或决策者模型慢，或超时设得太长 | 等待，或调小「总超时」 |
| 结果只有决策者视角，成员像没参与 | 成员 Key 全部失败或超时，降级为决策者独答 | 检查成员 Key 的健康、密钥、模型名是否正确 |
| 报错提到「决策者」 | 决策者 Key 不可用 | 换一个有效的决策者 Key |
| 开了检索但模型说没看到文件 | 工作目录填错，或该目录没有相关文件 | 核对目录路径；装了 `ripgrep` 检索会更快 |

## 关于容错

- **成员失败会被静默跳过**：某个成员的 Key 不可用时，该成员被跳过，其余成员照常出结果。
- **决策者失败会明确报错**：决策者是必需的，它不可用时整次聚合失败，不会假装成功。
